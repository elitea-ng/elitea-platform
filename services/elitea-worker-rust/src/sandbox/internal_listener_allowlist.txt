# The Rust worker's internal listeners: the reviewed allowlist (ADR-0059
# decision 7, "Internal paths"; story R1.9). surface_allowlist_tests.rs (beside
# this file, run by the worker job of ci-rust.yml) compares it with the tonic
# services the crate's non-test source serves and with every listener and
# registration site of that source, both ways. The format and the meaning of
# each field are at the top of surface_allowlist_tests.rs.
#
# The default worker binary serves nothing. The elitea-sandbox-supervisor
# binary (feature sandbox-supervisor) serves one mTLS listener per runtime
# profile (sandbox/process.rs run_profiles): the client certificate must chain
# to the profile's CA, and each request carries a grant elitea-main signed for
# this supervisor's audience, bound to one run (its claim and fence). None of
# the methods writes provider, policy, identity or role data: they run, read
# and remove sandbox containers and their ledger rows. An "admin" line here
# would have to be decided by Main's route and listed in docs/ARCHITECTURE.md.
#
# A grpc line names the file that names the service's tonic server module (and
# so builds the server). The profile file beside it binds the listener and
# registers the server (the site lines below).
