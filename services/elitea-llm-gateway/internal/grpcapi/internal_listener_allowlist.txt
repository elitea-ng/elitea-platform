# elitea-llm-gateway's internal listeners: the reviewed allowlist (ADR-0059
# decision 7, "Internal paths"; story R1.9). The gateway is outside go.work, so
# R1.8's tests in the workspace cannot see it; ci-gateway.yml runs these:
#
# - internal/grpcapi/surface_allowlist_test.go compares the grpc lines with
#   what the real GatewayService listener (grpcapi.NewServer) reports through
#   grpc.Server.GetServiceInfo(), both ways;
# - internal/server/surface_allowlist_test.go compares the site lines and the
#   http lines named by a file with the module's source (the health and
#   metrics mux, every listener and registration site), and the http lines of
#   the `llm` listener with the routes the /llm chi router registers
#   (chi.Walk over api.NewRouterWithLog), both ways.
#
# The format and the meaning of each field are in
# internal_listener_checks_test.go (the same file as R1.8's).
#
# The gateway writes no provider, policy, identity or role data through any
# listener: it READS provider credentials, governance definitions and model
# mappings from PostgreSQL, which elitea-main writes through its public API.
# What its calls write is run and metering data: the per-request log row
# (requestlog middleware on the router root, every /llm route) and the budget
# counters and usage events on NATS. An "admin" line here would have to be
# listed in docs/ARCHITECTURE.md and decided by Main's route.

# --- gRPC listener (GATEWAY_GRPC_ADDR): elitea.gateway.v1.GatewayService ---------
# mTLS only (grpcapi.ServerTLS requires a client certificate from
# GATEWAY_TLS_CA_FILE) and the Allowlist interceptor admits only the workload
# identities in GATEWAY_GRPC_CLIENTS (elitea-main by default). Each /llm call
# also carries Main's HMAC-signed identity tuple, verified by the handler.
# Every RPC runs the /llm chi router below in process (bridge.go).
