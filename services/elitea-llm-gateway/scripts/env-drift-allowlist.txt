# env-drift-check.sh allowlist — env vars the gateway code reads that are
# INTENTIONALLY not set via the Helm chart's `.Values.env` map. One name per
# line; blank lines and # comments ignored. An allowlisted var is never a FAIL
# and is not reported as drift.
#
# Keep this list SMALL and justified — every entry is a var an operator must
# supply out-of-band. If you add one, say why.

# Injected by the mtls.enabled conditional block in templates/deployment.yaml
# (deliberately NOT in the env map to avoid duplicate keys).
GATEWAY_TLS_CERT_FILE
GATEWAY_TLS_KEY_FILE
GATEWAY_TLS_CA_FILE

# Optional OpenTelemetry export — off unless an operator opts in with a collector
# endpoint; safe defaults when unset.
OTEL_EXPORTER_OTLP_ENDPOINT
OTEL_SERVICE_NAME

# Injected by the platform at deploy time (image tag → version), not chart config.
SERVICE_VERSION

# NOTE: SECRETS_MASTER_KEY was previously allowlisted (no chart wiring). It is now
# wired via the chart's `secrets:` block (valueFrom.secretKeyRef), so it is
# chart-settable and no longer needs an allowlist exemption. Same for
# GATEWAY_IDENTITY_SECRET.

# Hop-marker key material (issue #164). The gateway stamps
# internal/hopmarker.Header on every outbound provider request and refuses an
# inbound request that already carries this deployment's own marker, which
# contains a circular route on its first re-entry.
#
# Allowlisted because it is OPTIONAL and never silent. Empty leaves hop
# detection unarmed, which is a supported posture, and main() states the mode
# once at startup (logHopMarkerMode) — so the failure this gate exists to
# prevent, a feature that is quietly dead in the deployed pod, cannot happen
# here without a WARN line saying exactly that.
#
# It is a SEPARATE secret from GATEWAY_IDENTITY_SECRET and must never be
# derived from it: the marker travels to every upstream, and a provider
# api_base is tenant-authored.
#
# STILL OUTSTANDING: the chart offers no knob, so a default install boots
# loudly UNARMED. Wiring `secrets.GATEWAY_HOP_SECRET` in
# deploy/helm/elitea/values.yaml beside GATEWAY_IDENTITY_SECRET, with the same
# value on every replica, is what arms a default install. Delete this entry
# when that lands.
GATEWAY_HOP_SECRET

# The development-only opt-out from the mandatory vault master key
# (cmd/elitea-llm-gateway/master_key_gate.go). It is absent from values.yaml on
# purpose: a default there would ship the unwrapped posture. A throwaway install
# sets it as llmGateway.env.ELITEA_DEV_ALLOW_UNWRAPPED_SECRETS, and the chart
# then makes the key reference optional (elitea-llm-gateway.masterKeyRef).
ELITEA_DEV_ALLOW_UNWRAPPED_SECRETS
