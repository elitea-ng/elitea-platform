## The first message of a desktop thread shows at once, and keeps its team

In the desktop app, the first message of a new **Local work** thread now shows in the thread as soon as you send it, marked **Preparing workspace…** while the app creates the conversation and, with **Work in** set to **New worktree**, the worktree. You can write your next message meanwhile. If the preparation fails, the message stays marked **Not sent** with **Retry**. A team or agents you added before the first message now stay with the thread when it moves to its new worktree, so the lead and its companions answer from the first turn. The right sidebar also stays on **Participants** when you add a team. On the web, a new chat's first message also shows before the chat is created. See [Work in a worktree](/menus/settings/desktop-account-menu#work-in-a-worktree).

The participants list now shows each agent's avatar pack or icon in the agent's row, moving with what the agent does, with the first letter only for an agent that has neither, and no second avatar beside the status. In the desktop app, uploaded avatar images and video loops no longer show as broken images. See [Agent avatars](/menus/chat#agent-avatars).
