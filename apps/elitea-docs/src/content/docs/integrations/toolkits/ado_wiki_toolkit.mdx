Read and update pages in an Azure DevOps wiki. It's listed under the **documentation** category in the toolkit type picker.

## Prerequisites

- An account at ADO wiki with permission to issue an API token or credential, saved in Elitea as a **`ado`** credential (`/credentials/create-credential/<type>`).
- Or skip the saved credential and paste `token` directly into the toolkit's own settings (inline auth).
- If you plan to index content for retrieval: an embedding model, configured under AI providers.

## Connect the toolkit

<Steps>
<Step title="Open the toolkit type picker">
In the left navigation, open **Toolkits**, then select **New**. Filter the type picker by the **documentation** category, or search for "ADO wiki".
</Step>

<Step title="Pick or create a credential">
Under the credential field, choose an existing **ado** credential, or select **Create credential** to add one without leaving the form.
</Step>

<Step title="Add indexing settings (optional)">
If you plan to index this source, set an **embedding model**. Indexes are kept in the platform's vector store, so there is no vector-storage setting to pick. Leave it empty to use the toolkit without indexing.
</Step>

<Step title="Set the image defaults (optional)">
**Process Images** and **Image Description Prompt** set the default of the `process_images` and `image_description_prompt` arguments for **Get wiki page**, **Get wiki page by path** and **Get wiki page by id**. A call that sets an argument overrides the toolkit value. Leave a field empty to keep each tool's own default: on. Two toolkits of this type in one agent can have different defaults.
</Step>

<Step title="Save">
Name the toolkit and select **Create**. It's now available to attach to agents, pipelines and conversations in this project.
</Step>
</Steps>

## Common issues

<Note>
With `process_images` on, the agent worker describes the images in the page content with the agent's chat model, and uses `image_description_prompt` when it is set:

- The description replaces the link of each image: `![name](/.attachments/a.png)` becomes `![name](description)`.
- **Get wiki page** describes images only when `include_content` is on.
- The worker reads only wiki attachments (`/.attachments/...`), from the wiki repository, through the toolkit connection. It does not get images from other sites. These images keep their link and get a note.
- A link to a file that is not an image, for example a PDF, does not change.
- One call describes a maximum of 20 images and downloads a maximum of 12 MB. A larger image (more than 5 MB) is not described.
- When the worker cannot read or describe an image, it adds a short note below the link, for example `[image unavailable: ...]`. The tool call does not fail.
- When the agent has no chat model, the page comes back with the images not described.
</Note>

<Note>
The Indexes tab only appears when the configured worker can run this type's `index_data` tool; if the worker can't, the tab is hidden and shows the worker's refusal message. `index_data` itself can't be run from the Test tools pane — use the Indexes tab.
</Note>

<Note>
The credential form for ADO wiki supports **Check connection** — use it before saving to confirm Elitea can reach ADO wiki with these details, instead of discovering an auth problem from a failed tool call later.
</Note>
