Read and manage Azure DevOps boards: work items, queries and area/iteration paths. It's listed under the **project management** category in the toolkit type picker.

## Prerequisites

- An account at ADO boards with permission to issue an API token or credential, saved in Elitea as a **`ado`** credential (`/credentials/create-credential/<type>`).
- Or skip the saved credential and paste `token` directly into the toolkit's own settings (inline auth).
- If you plan to index content for retrieval: an embedding model, configured under AI providers.

## Connect the toolkit

<Steps>
<Step title="Open the toolkit type picker">
In the left navigation, open **Toolkits**, then select **New**. Filter the type picker by the **project management** category, or search for "ADO boards".
</Step>

<Step title="Pick or create a credential">
Under the credential field, choose an existing **ado** credential, or select **Create credential** to add one without leaving the form.
</Step>

<Step title="Add indexing settings (optional)">
If you plan to index this source, set an **embedding model**. Indexes are kept in the platform's vector store, so there is no vector-storage setting to pick. Leave it empty to use the toolkit without indexing.
</Step>

<Step title="Set the image defaults (optional)">
**Process Images** and **Image Description Prompt** set the default of the `process_images` and `image_description_prompt` arguments for **Get work item** and **Get comments**. A call that sets an argument overrides the toolkit value. Leave a field empty to keep each tool's own default: on for Get work item, off for Get comments. Two toolkits of this type in one agent can have different defaults.
</Step>

<Step title="Save">
Name the toolkit and select **Create**. It's now available to attach to agents, pipelines and conversations in this project.
</Step>
</Steps>

## Common issues

<Note>
With `process_images` on, the agent worker describes the images in the result with the agent's chat model, and uses `image_description_prompt` when it is set:

- **Get comments** adds an `image-description` attribute to each `<img>` tag. Below each markdown image, it adds a line `[image-description: ...]`.
- **Get work item** describes the images in the fields only when `parse_attachments` is also on.
- The worker reads each image through the toolkit connection, with the same limits as **Get image by url**. One call describes a maximum of 20 images and downloads a maximum of 12 MB. A larger image (more than 5 MB) is not described.
- The worker reads each image one time, also when the result refers to it more than one time.
- When the worker cannot read or describe an image, it adds a short note, for example `[image unavailable: ...]` or `[image skipped: ...]`. The tool call does not fail.
- When the agent has no chat model, the result comes back with the images not described.
</Note>

<Note>
The Indexes tab only appears when the configured worker can run this type's `index_data` tool; if the worker can't, the tab is hidden and shows the worker's refusal message. `index_data` itself can't be run from the Test tools pane — use the Indexes tab.
</Note>

<Note>
The credential form for ADO boards supports **Check connection** — use it before saving to confirm Elitea can reach ADO boards with these details, instead of discovering an auth problem from a failed tool call later.
</Note>
