Beyond the toolkits with their own page, the type picker offers 15 more types. Most configure a single whitelisted API call rather than a rich tool set, or cover a Zephyr variant that isn't Zephyr Scale or Zephyr Enterprise. Each row below states whether the agent worker runs it — see [Toolkits](/menus/toolkits) for what a greyed-out tile means.

## Cloud and infrastructure

Each of these wraps a single provider API in one or two generic call tools; none needs a saved credential beyond what the provider's own client library picks up from the worker's environment, except where noted.

| Type | Label | What it does | Auth | Worker |
|---|---|---|---|---|
| `aws` | Cloud AWS | Runs one whitelisted AWS API call (`execute_aws`). | none | No |
| `azure` | Cloud Azure | Runs one whitelisted Azure API call, plus a health check. | none | Yes |
| `gcp` | Cloud GCP | Runs one whitelisted Google Cloud API request. | none | Yes |
| `k8s` | Cloud Kubernetes | Runs one whitelisted `kubectl`-style command, plus a health check. | none | Yes |
| `keycloak` | Keycloak | Runs one whitelisted Keycloak admin API request. | none | Yes |
| `localgit` | Local GIT | Reads, diffs and commits files in a Git checkout the worker can reach on disk. | none | No |

<Note>
`aws` and `localgit` are not run by the agent worker; their tiles show greyed out with a reason.
</Note>

## AWS Delta Lake

The `delta_lake` toolkit reads one Delta Lake table in Amazon S3 with the AWS key pair, region and `s3_path` (or `table_path`) of a `delta_lake` credential. Its tiles stay out of the **New toolkit** picker (the type is hidden, as in the SDK it comes from); a toolkit created through the API or imported from the SDK runs on the agent worker. It has three read-only tools, with the SDK's names and arguments:

| Tool | What it does |
|---|---|
| `query_table` | Returns rows, optionally with `columns` (which to keep), `query` (a pandas query string) and `filters` (structured conditions). `query` and `filters` both apply. |
| `vector_search` | Returns the `k` rows (default 5, at most 100) whose `embedding_column` (default `embedding`) is most similar to the `embedding` you give, by cosine similarity, best first. Rows with no embedding are skipped. |
| `get_table_schema` | Returns the table's schema, one `name: type` line per column. |

**Filters.** `filters` is an object of `column: condition`. A condition is a value (the column equals it), a list (the column is one of them), `null` (the column is null), or an object of operators that must all hold: `eq`, `ne`, `in`, `gt`, `gte`, `lt`, `lte`, `is_null`. Columns are combined with AND. Numbers compare as numbers, text as text (dates and timestamps as their ISO text), booleans as booleans. `ne` also matches nulls and values of another type, as pandas `!=` does. Comparisons on integer, double and string columns (including partition columns) also let the reader skip whole files.

```json
{"columns": ["id", "name"], "filters": {"score": {"gte": 20, "lt": 45}, "name": ["bob", "dave"]}}
```

**Query.** `query` takes the pandas `DataFrame.query` syntax, literals only: comparisons (`==`, `!=`, `<`, `<=`, `>`, `>=`, chained like `1 < id <= 3`, also between two columns), `and` / `or` / `not` (and `&`, `|`, `~`, which rank with `and` / `or`, below the comparisons, as in pandas' default parser) with parentheses, `in` / `not in` against a list (`name in ['a', 'b']`), `is null` / `is not null` (`is None`), the arithmetic `+ - * / %`, and backtick-quoted column names. It is read by a bounded parser and never executed. Anything else (function or method calls such as `.str.contains()`, `@variable`, `**`, `//`, `like`, subqueries) is refused with a message naming the offending token and its position. An empty or null `query` returns every row.

```json
{"query": "score >= 20 and name in ['bob', 'dave'] and not (id == 4)"}
```

**Limits.** The SDK loads the whole table into memory. Here a read is bounded: an answer carries at most 1,000 rows and 1 MiB (a final `_truncated` entry says when more matched), a text cell is cut at 2,000 characters, and a read that would scan more than 5 million rows or 512 MiB, or take longer than a minute, fails with a message asking you to narrow it with `columns` and `filters`. The credential's path must be an `s3://` URI; the worker reads no local path.

The worker calls only `s3.<region>.amazonaws.com` (`.com.cn` for a `cn-` region). Deployments that restrict worker egress allow it automatically for a run that uses the toolkit. Test Connection is not available for this credential type.

## Communication and testing

| Type | Label | What it does | Auth | Worker |
|---|---|---|---|---|
| `yagmail` | Yet Another Gmail | Sends an email through a Gmail account. | none | Yes |
| `carrier` | Carrier | Triggers and reads Carrier backend/UI test runs and reports. | saved credential: `carrier` | Yes |
| `zephyr` | Zephyr | Adds and reads Zephyr test case steps — the base Zephyr integration, distinct from Scale/Enterprise/Squad below. | none | Yes |
| `zephyr_squad` | Zephyr Squad | Test steps, executions, cycles and BDD content for Zephyr Squad. | none | Yes |
| `zephyr_essential` | Zephyr Essential | The largest Zephyr integration: test cases, cycles, executions, folders, issue links and BDD content, plus indexing (`index_data`). | saved credential: `zephyr_essential` | Yes |

## Connect one of these toolkits

<Steps>
<Step title="Open the toolkit type picker">
In the left navigation, open **Toolkits**, then select **New**. Filter the tile grid by category (cloud, testing, and so on), or search by name.
</Step>
<Step title="Fill in the credential, if any">
Types with a saved-credential column above need one created first (or inline via **Create credential** in the form); the rest only take a project/host/namespace-style setting.
</Step>
<Step title="Save">
Name the toolkit and select **Create**.
</Step>
</Steps>

## Common issues

<Note>
A type whose worker column says No for your deployment doesn't error loudly — its tile is simply absent from the picker (`metadata.hidden=true`). If a type you expect is missing, check the worker column above before assuming it doesn't exist.
</Note>
