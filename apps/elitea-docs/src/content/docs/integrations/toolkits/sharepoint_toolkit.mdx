Read and update files and lists in a SharePoint site. It's listed under the **office** category in the toolkit type picker.

## Prerequisites

- An account at SharePoint with permission to issue an API token or credential, saved in Elitea as a **`sharepoint`** credential (`/credentials/create-credential/<type>`).
- If you plan to index content for retrieval: an embedding model, configured under AI providers.

## Connect the toolkit

<Steps>
<Step title="Open the toolkit type picker">
In the left navigation, open **Toolkits**, then select **New**. Filter the type picker by the **office** category, or search for "SharePoint".
</Step>

<Step title="Pick or create a credential">
Under the credential field, choose an existing **sharepoint** credential, or select **Create credential** to add one without leaving the form.
</Step>

<Step title="Add indexing settings (optional)">
If you plan to index this source, set an **embedding model**. Indexes are kept in the platform's vector store, so there is no vector-storage setting to pick. Leave it empty to use the toolkit without indexing.
</Step>

<Step title="Save">
Name the toolkit and select **Create**. It's now available to attach to agents, pipelines and conversations in this project.
</Step>
</Steps>

## Common issues

<Note>
The Indexes tab only appears when the configured worker can run this type's `index_data` tool; if the worker can't, the tab is hidden and shows the worker's refusal message. `index_data` itself can't be run from the Test tools pane — use the Indexes tab.
</Note>

<Note>
The tools act as the signed-in person: the credential needs an OAuth discovery endpoint so each person authorizes SharePoint once. A credential without one (app-only access with a client secret) can't be used by agents, and the toolkit is reported as not enabled with that reason. Microsoft retired app-only access to the OneNote API, so the OneNote tools need the signed-in access in any case. Text and Office files are read as text, pictures in them aren't described, and a change (an upload, a new list item, an edit in OneNote) is sent once: if SharePoint doesn't confirm it the agent is told the outcome is unknown and checks before repeating it.
</Note>

<Note>
There's no connection check on this form. Save the toolkit, then run one read-only tool from the editor's Test tools pane to confirm the credential works before attaching SharePoint to an agent.
</Note>
