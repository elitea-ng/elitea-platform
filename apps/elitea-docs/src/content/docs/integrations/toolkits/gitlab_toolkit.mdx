Read and write files, branches, issues and merge requests in a single GitLab project. It's listed under the **code repositories** category in the toolkit type picker.

## Prerequisites

- An account at GitLab with permission to issue an API token or credential, saved in Elitea as a **`gitlab`** credential (`/credentials/create-credential/<type>`).
- If you plan to index content for retrieval: an embedding model, configured under AI providers.

## Connect the toolkit

<Steps>
<Step title="Open the toolkit type picker">
In the left navigation, open **Toolkits**, then select **New**. Filter the type picker by the **code repositories** category, or search for "GitLab".
</Step>

<Step title="Pick or create a credential">
Under the credential field, choose an existing **gitlab** credential, or select **Create credential** to add one without leaving the form.
</Step>

<Step title="Add indexing settings (optional)">
If you plan to index this source, set an **embedding model**. Indexes are kept in the platform's vector store, so there is no vector-storage setting to pick. Leave it empty to use the toolkit without indexing.
</Step>

<Step title="Save">
Name the toolkit and select **Create**. It's now available to attach to agents, pipelines and conversations in this project.
</Step>
</Steps>

## Issues and merge requests

**Get issues** returns a compact list (title, number, state, labels, author, created and updated time) and takes filters: **state** (`opened` by default, `closed`, `all`), **labels**, **author_username**, created and updated time windows, **page** and **per_page** (20 by default), or **fetch_all** to read every page. An upper bound given as a bare date covers the whole day.

**List merge requests** and **Get merge request** give compact merge request metadata without diffs, for throughput, cycle time and aging questions. List merge requests filters by state, time window, source and target branch, author and labels, and **include_details** adds assignees and reviewers. Get merge request takes the merge request's IID and adds discussions, approvals, the latest pipeline or the commits only when you ask for them with the matching **include_** flag; one that cannot be read becomes a one-line notice instead of failing the call. For the diff itself, use **Get pr changes**.

The Indexes tab only appears when the configured worker can run this type's `index_data` tool; if the worker can't, the tab is hidden and shows the worker's refusal message. `index_data` itself can't be run from the Test tools pane — use the Indexes tab.
