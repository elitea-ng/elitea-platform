title: "Hardening checklist"
description: "The settings a regulated deployment turns on, in order, each with the page that explains it."
---

A default install favours getting started. A deployment that will be assessed against enterprise risk controls should work through this list. Each item links to the page that explains the setting, its default and what it changes for users.

## Supply chain

- [ ] Verify the signature and build provenance of the chart and images before you install or upgrade. Enforce the signature with an admission policy, so the cluster refuses an image the Elitea release workflow did not sign. See [Verify release artifacts](/deployment/verify-artifacts).
- [ ] Import the image SBOMs into your vulnerability management, so a new CVE in a shipped package reaches you between releases.

## Identity and credentials

- [ ] Use SSO (OIDC or SAML) and SCIM provisioning. Assign project roles through groups, not by hand. See [Authentication](/admin/authentication).
- [ ] Turn on the credential governance profile, so agents run under their own identity and every credential use needs an approved grant. See [Credential governance](/deployment/credential-governance) and its [runbook](/deployment/credential-governance-runbook).
- [ ] Store toolkit secrets in Vault or OpenBao through the secret-store integration. See [Secrets](/admin/secrets).
- [ ] Set personal access tokens to expire, and keep expiry notices on.

## Tools and network

- [ ] Restrict toolkit types per project, and block tools you do not use. See [App requests and toolkit types](/admin/app-requests-and-toolkit-types).
- [ ] List destructive and outward-facing tools as sensitive, so every call pauses for approval. See [Sensitive action authorization](/how-tos/chat-conversations/sensitive-action-authorization-guardrail).
- [ ] Keep the egress guard on. Add private hosts to the allow-list only when a toolkit needs them. See [Configuration](/deployment/configuration).
- [ ] Seed the worker egress allowlist from **Configuration › Worker Egress**, then set its mode to `allowlist`. See [Least privilege and trust](/admin/enterprise-controls/least-privilege-and-trust).
- [ ] Set a maximum idle timeout and session lifetime under **Configuration › Session Policy**. See [Authentication](/admin/authentication#session-policy).
- [ ] Set **Maximum Run Time** under **Configuration › Run Caps** above your longest legitimate run. See [Runtime safety](/admin/enterprise-controls/runtime-safety#whole-run-time-cap).

## Runtime safety

- [ ] Decide who may stop agents and projects, and who may stop the whole platform. Grant the permissions to those roles only. See [Runtime safety](/admin/enterprise-controls/runtime-safety).
- [ ] Keep the kill-switch self-test enabled, and alert on its last-success metric. See the [emergency stop runbook](/deployment/emergency-stop-runbook).
- [ ] Set project budgets. A reached budget refuses further model calls. See [Budgets and LLM governance](/admin/budgets-and-governance).

## Change control

- [ ] Set each production agent's risk tier and owners. Agents that existed before the upgrade start at `medium`. See [Agent lifecycle](/admin/enterprise-controls/agent-lifecycle#registry-and-risk-tiers).
- [ ] Review the tier policy under **Configuration › Agent Lifecycle**: approvals, recertification cadence and mandatory attestations. Set **Lapse action** to `suspend` if a lapsed certification must stop the agent. See [Configure the tier policy](/admin/enterprise-controls/agent-lifecycle#configure-the-tier-policy).
- [ ] Decide who holds `models.applications.governance`. By default every project admin holds it.
- [ ] Mark a release gate suite on every agent at tier `high` or `critical`, and a regression suite. See [Evaluation gate](/admin/enterprise-controls/agent-lifecycle#evaluation-gate).
- [ ] Give your GRC tool an API token with `lifecycle.attestations.write`, so review outcomes are recorded as attestations.

## Evidence and data

- [ ] Configure the audit export to your SIEM, and keep the copy of record in WORM storage. See [Audit trail](/admin/audit-trail) and [Audit event schema](/reference/audit-event-schema).
- [ ] Set the maximum retention for each data class to match your records schedule. Know how to place a legal hold before you need one. See [Audit evidence and retention](/admin/enterprise-controls/audit-evidence-and-retention).
- [ ] Alert on audit-export lag and dead letters (the chart ships the rules). The `run_steps` stream is included.
- [ ] Set the `step_content` and `step_record` maximums, and set `evidence_fields` on toolkits whose results carry data you must not keep. See [Run step records](/admin/enterprise-controls/audit-evidence-and-retention#run-step-records).
- [ ] Grant `runs.evidence.read` only to the roles allowed to read prompts and tool results, and review the content-read rows in the audit trail.
- [ ] Verify a sample of run chains and the admin audit trail chain on a schedule, and compare run anchors with your SIEM copy. See [Reconstruct an agent run](/admin/enterprise-controls/reconstruct-a-run).

## Keep it current

This checklist grows as the controls in the [catalogue](/admin/enterprise-controls/overview) ship. Re-read it after each upgrade: the "What's new" page lists every new control and its default.
