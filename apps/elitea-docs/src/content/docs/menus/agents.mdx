An agent combines instructions, a model, and optional toolkits and skills into a reusable assistant. This page covers the Agents menu end to end; for the underlying concept, see [What is an agent](/home/key-concepts#agent).

<Screenshot id="agents-list" alt="The Agents dashboard listing project agents" />

The Agents page lists the project's agents. Its toolbar has the search box, **Filters** (tags and authors, in the side panel), the card/table switch, **Import** and **+ New agent**; see [Page layout](/menus/page-layout). The **My liked** and **Trending** tabs are hidden until they are supported.

## Create an agent

<Steps>
  <Step title="Open the form">
    Select **+ New agent** in the Agents page toolbar, or the **+** next to **Agents** in the sidebar.
  </Step>
  <Step title="Fill in General and Instructions">
    **Name** and **Description** are required; **Instructions** define the agent's behavior. Tags, a welcome message, and up to four conversation starters are optional.
  </Step>
  <Step title="Save">
    Saving creates the agent's first ("latest") version and opens its full configuration page: a form on the left, a live test chat on the right.
  </Step>
</Steps>

<Tip title="Build or edit with AI">
Select **Build with AI** on a new agent, or **Edit with AI** on a saved one, to describe what you want in plain language and review a generated draft — name, description, instructions, welcome message, starters, and suggested toolkits — before applying it.
</Tip>

## Attach toolkits, agents, MCPs, and pipelines

In the **Tools** section, use the **+Toolkit**, **+MCP**, **+Agent**, and **+Pipeline** buttons to attach existing resources; each opens a searchable picker with a **Create new** option that takes you to that resource's own creation form. Changes save automatically.

<Note>
If an attached toolkit uses shared credentials that require your own private copy, a **Credential setup required** banner appears on its card — select **Create a credential** to add the matching private credential.
</Note>

### Skills

Attach up to five [skills](/menus/skills) per agent version from the **Skills** section. Each attached skill uses its `base` version by default; select the version name on the card to switch to a different one. The Skills section is hidden when the Public project is selected.

### Modules

Built-in modules — attachments, image creation, data analysis, planner, smart tools selection, swarm mode, and the platform's own MCP tools — turn on in **Tools** › **Modules**. Image creation, swarm mode and the platform's MCP tools show disabled with a reason: the platform's worker does not run them. See [Internal tools](/menus/internal-tools).

### Instructions, variables, and mentions

The Instructions field is a text input: it starts compact and grows with what you type, and the expand button opens it full screen for long instructions. Type `/` in Instructions to mention a toolkit, MCP, agent, or pipeline already attached to the agent, and `~` to mention an attached skill. A `{{variable_name}}` placeholder in Instructions automatically adds a matching input field to the **Variables** section.

### Editor notes

A free-text **Editor Notes** field records internal context about the current version — it is never sent to the model or used during execution.

### Output contract

In **Advanced**, **Output contract** sets a rule for the agent's final answer: a JSON Schema, a regular expression, or a named format (`json`, `markdown` or `csv`). The worker validates each final answer. If an answer is not valid, the worker asks the model one more time, with the validation error. If the second answer is also not valid, the run stops with `OUTPUT_CONTRACT_VIOLATION`. An agent with a contract shows its answer only after the answer is validated. Select **None** to remove the contract. See [Output contracts](/admin/enterprise-controls/content-controls#output-contracts).

### Require citations

In **Advanced**, **Require citations** tells the agent to cite the tool results that it uses, as `[1]`, `[2]`. The chat then shows under each answer how many sources the answer cites and how many statements have no citation. This is not a confidence score. A cited source does not prove that the source supports the statement. See [Grounding indicators](/admin/enterprise-controls/content-controls#grounding-indicators).

## Persona

The **Persona** tab holds the version's persona: how the agent speaks and behaves. Fill in what you need:

- **Display name**, **Pronouns** and **Role** (one line, shown in the participant list).
- **Voice**, **Values** and **Boundaries** (what the agent declines or always escalates), one entry per line.
- **Relationships**: how the agent treats other agents and people, one `agent: stance` pair per line.
- **Proactive goals**: read by the heartbeat. They are not put into the prompt.
- **Body**: free-form markdown.

The persona is saved with the version by **Save**, like the other fields. Leave every field empty to remove it. A persona grants nothing: it cannot name a tool, a toolkit, a credential, a secret, a permission or a scope, and Save refuses one that tries (`soul_capability_key`). It holds at most 16384 bytes of text; the counter under the fields shows how much is used.

The model reads the persona after the platform's own text and your organization's guardrails, and before the instructions and recalled memory. A persona is part of the version: changing it changes what a release pins, and export, import and fork carry it.

In the desktop app, a `SOUL.md` file at the root of a Local work folder, next to `AGENTS.md`, gives that folder's agent a persona. It has the same fields: YAML front matter for every field but the body, then the body as markdown.

## Avatar

The **Avatar** tab holds the version's avatar pack: the pictures the chat shows for the agent. It has one card for the **Still** and one for each state (idle, thinking, speaking, working, waiting, success, error and waking). Each card shows the slot as the chat shows it, so you see every state before you save.

- **Still**: a PNG, JPEG, WebP or SVG image. The chat shows it when nothing moves, and it is the agent's icon everywhere else. Add it first.
- **A state**: an image, an animated WebP, or a muted MP4 (H.264) or WebM (VP9 or AV1) loop. A video uses the still as its poster. A state with no file shows the still with the [default motion](/menus/chat#agent-avatars).

Select **Upload** on a card to fill it, or **Remove** to clear it. Removing the still removes the whole pack. Every file is at most 2 MiB and 512 px, and a loop is at most 4 seconds and plays forever. The server reads the file type from the file itself, not from its name. It refuses a file that breaks a rule and says why, for example a video with sound or an SVG with a script. Lottie and Rive files are not accepted.

When the project has an image generation model, **Generate** makes the pictures for you. **Generate stills** makes four candidates from the persona's display name, role and voice; select one to use it as the still. **Generate loop** makes a looping animated WebP of the still for the state you choose; its frames are made at the same time, so a loop takes about as long as one picture. The project's budget pays for each call. There is no video generation.

The pack is saved with the version by **Save**, like the other fields. Save also makes the still the version's icon, so an older app shows it. Publishing and a new version keep the pack. **Fork** copies the pack and its files into the target project. **Export** puts the files in the exported file, and **Import** stores them in the project you import into, so the pack survives a move to another installation.

A generated or uploaded file that no version uses is deleted after 7 days. That includes the candidates you did not pick.

## Test the agent

The embedded chat panel on the right (below the form on a narrow screen) lets you send messages, pick a model and its settings (Reasoning for reasoning models, Creativity for standard ones, Max Completion Tokens), and iterate without leaving the page. It is there when the page opens, also right after you create the agent, and starts its conversation when you first click into the message box. Opening the page, **Clear chat** and the model picker start nothing. That conversation belongs to the agent and does not appear in your **Chats** list; coming back to the agent's page picks it up again. The panel runs the saved version, so save to try your latest edits; **Clear chat** deletes the conversation and starts over. To keep a conversation with the agent in **Chats**, click **Open in Chats** in the toolbar. When context management is on for the project, a Context Budget widget appears above the panel after the first message.

## Versions

Selecting **Save** again updates the current version. Use **Save As Version** to branch off a named version instead — version names must be 48 characters or fewer, without spaces or underscores. From any version you can **Delete**, **Execute**, or switch versions from the version dropdown. See [Entity versioning](/how-tos/agents-pipelines/entity-versioning).

### Publish, export, import, and fork

- **Publish** a draft version through a guided wizard with automated AI validation, making it visible in [Catalog](/menus/catalog). See [Agent publishing](/how-tos/agents-pipelines/publishing).
- **Export** downloads the selected version as a single `.md` file, or a `.zip` if it references nested agents.
- **Import** an exported file from the Agents page toolbar.
- **Fork** copies the selected version into another project you choose.

See [Import/export](/how-tos/agents-pipelines/import-export) and [Forking](/how-tos/agents-pipelines/forking) for full detail; toolkit credentials must be reconfigured manually after either operation.

## Evaluation

A saved agent's editor includes an **Evaluation** tab to define what "good" looks like for that agent, run it against test cases, and see how it scored.

<Tabs>
  <Tab title="Library">Define scoring dimensions — the criteria a run is judged against, such as accuracy or tone — building up a reusable set of judging criteria before running anything.</Tab>
  <Tab title="Datasets">Create a dataset of test cases: inputs paired with what you expect the agent to do with them. A run executes against a dataset.</Tab>
  <Tab title="Runs">Start a run against a dataset and your dimensions. Runs poll for progress while this tab stays open — leaving it pauses polling until you return — and produce a scorecard with one score per dimension per case when they finish.</Tab>
</Tabs>

### Human scores

A dimension that allows only the **Human** engine is scored by a person. A run still answers every case, but it does not call the AI judge for that dimension: the case shows **Waiting for a human score** on the run's scorecard, with no number. A reviewer enters a score (on the dimension's own scale: 0 or 1 for a yes/no dimension, otherwise between its minimum and maximum) and an optional note, and **Save score**. The case then shows the score, and the run's overall score is recalculated from the scored cases; cases still waiting do not count, and are not treated as zero.

Scores are never overwritten. **Re-score** adds a new one, the newest is the score in force, and each shows who gave it and the note. Reading scores needs the evaluation human-score read permission and entering one needs the human-score create permission; project admins and editors have the create permission, and viewers can read. The release gate treats a case that is still waiting for a human score as undecided, so a gate with a human dimension stays pending until every case is scored. A dimension that allows both the AI and Human engines is scored by the AI judge.

### Run limits

**Run limits** (a button on the Runs tab) saves a named set of limits you pick when you start a run: tokens and cost (an estimate in USD from the price list) **per case** and **per run**, and what the run does when the **run** limit is reached: **Stop the run** (the run ends as errored, says which limit it reached, and keeps the cases it scored) or **Only report it** (the run finishes and shows a **Token limit reached** or **Cost limit reached** note). Leave a field empty for no limit.

The limits are checked from the usage already recorded for the run, between model calls, so a run can pass a limit by the call that crosses it. A case that reaches its own limit is not judged further (its remaining judge results are skipped, with the reason), and the run goes on. Changing or deleting saved limits does not change runs that already started. Anyone who can read runs sees the limits; changing them needs the permission to start runs. Limits on steps, time and tool output are not offered: a case is a single model call with no tools today, so they would change nothing.

### Insights on a finished run

Open a finished run's scorecard to see three cards above the scores:

- **Consumption** shows the tokens and estimated cost of the agent's answers and of the judge, side by side, with a total. The money is an estimate at the catalogue rate. A run that started before consumption was recorded, or whose calls the gateway has pruned, says so instead of showing zero. The card needs the analytics permission.
- **Efficiency** shows the latency of the agent's answer at p50 and p95, how many answers timed out, and tokens and cost per case. Latency is recorded from now on; a run scored before that reads "not recorded".
- **Compared with the previous run** shows the change in the overall score, in each dimension's average, in p50 latency and in cost per case against the nearest earlier scored run of the same dataset.

These measure one model turn per case: the run does not use tools or toolkits, so there are no tool or trajectory metrics yet.

### Enhance with AI

When a finished run missed a target, the scorecard offers **Enhance with AI** (it needs the permission to start runs). The model reads the agent version the run scored and the results that missed, with the outputs and the judge's rationale, and proposes up to three kinds of fix, which you review one step at a time:

1. **Instructions**: a revised version of the instructions, shown as a diff. Accepting creates a new **draft** version of the agent, copied from the version the run scored (settings, variables, skills and toolkit bindings) with only the instructions changed. If the instructions are longer than 24000 characters, no instruction change is proposed and the step says why. Nothing is published: a draft follows the agent's normal release path, so an agent above low risk goes through a change request and its release gate. Use **Request publish** in the last step, or publish from the agent page.
2. **Rubrics and targets**: a changed rubric or target for a dimension. The step shows the target the run was judged against; accepting changes the dimension's default, which new runs use. This run keeps the rubric and target it was scored with. A proposed target must lie on the dimension's scale.
3. **Expected outputs**: a corrected expected answer for a case in the dataset.

Nothing is saved until the last step, and you can untick any change. Saving can be repeated: it retries only the fixes that failed. Each saved fix goes through the same permissions as editing it by hand, and a refused one is reported with its reason while the others are still saved.

## History

A saved agent's editor also includes a **History** tab: every past conversation that used this agent, newest first, including the chats you had in the editor's own chat panel. Each entry shows the first message you wrote (the conversation's title if there is none), then its start time in your local time, the version, a derived duration, and its message count. Select a run to see the whole exchange, your message included, and below it the recorded trace: the tool calls and thinking steps the runtime logged for that conversation. An agent with no past conversations shows an empty state rather than a blank panel.

<Note>
Selecting a run in History does not currently reload that conversation into the Test panel above — there is no live restore path from this tab (issue #868, same disclosed gap as pipelines' equivalent History tab).
</Note>

## Best practices

<AccordionGroup>
  <Accordion title="Write clear instructions">Be specific about the agent's goal, scope, and constraints; give examples where useful.</Accordion>
  <Accordion title="Keep toolkits minimal">Attach only the toolkits and tools the agent actually needs.</Accordion>
  <Accordion title="Use named versions for real changes">Branch a version before a change you might need to roll back from.</Accordion>
  <Accordion title="Test before publishing">Run the agent through its conversation starters and a few edge cases before you publish it.</Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Agent responds slowly or not at all">Check the selected model and its settings, and confirm any attached toolkits are configured correctly.</Accordion>
  <Accordion title="Cannot publish">Confirm you have publishing permission and that all required fields are complete; review the AI validation result for blocking issues.</Accordion>
  <Accordion title="Skills button is disabled">Save the agent first — Skills can only be attached to a saved version — or check whether the five-skill limit has been reached.</Accordion>
</AccordionGroup>
