Chat is the central place where Elitea's capabilities come together. Each conversation is an independent session — you can reference earlier messages in the same conversation, but context is not shared between separate conversations. Conversations are stored on the server and accessible from any device.

## Create a conversation

1. Select **+** (**New chat**) in the sidebar's **Chats** caption, or select the **Chats** caption itself.
2. Start typing in the welcome screen's input.
3. Optionally add participants first — select **+** in the input toolbar, or type `#` to search.
4. Type your message and send it. The conversation name is generated automatically from the message content.

### Unsent messages

What you type but do not send stays with its conversation. Switch to another conversation, another project or a Local work thread, and when you come back the text is in the input for you to finish. A new chat keeps its own unsent text per project until you send it. Unsent text is kept on this device only (desktop app, browser or mobile app) and is cleared when you sign out.

## The chat list

Your conversations are in the sidebar, under **Chats** — the same list in the browser and the desktop app; the chat page has no list of its own. **Pinned** conversations come first, then your folders, then the date groups: **Today**, **Yesterday**, **Previous 7 days**, **Previous 30 days**, and **Older**. Pinned and Today are open; the older groups start closed and show how many conversations they hold. **Show more** at the end of a group loads the next page, and the **Archived** row at the end opens your archived chats.

- **Search** — select the magnifier in the Chats caption to filter the list by name. **Esc** clears and closes the search.
- **Local work only** — in the browser, the caption's **⋯** menu shows only conversations that came from Local work.
- **Conversation menu** — point at a conversation and select **⋯** (or right-click it in the desktop app) for **Open**, **Pin**/**Unpin**, **Rename**, **Move to folder…**, **Duplicate**, **Fork**, **Export** (Markdown or JSON), **Playback**, **Make public**/**Restrict access** (team projects, your own conversations), **Share by link**, **Copy Link**, **Archive**, and **Delete…**.

### Folders

Select the folder icon in the Chats caption to create a folder, then drag conversations into it or use **Move to folder…** from a conversation's menu. A folder's **⋯** menu has **Rename**, **Pin**/**Unpin**, and **Delete…**. In a personal project, folders and their contents are visible only to you. In a team project, folders can be shared with the whole project and cannot be converted back to private.

## Participants

Participants extend what a conversation can do:

  <Card title="Models" icon="microchip-ai">A language model you talk to directly.</Card>
  <Card title="Agents / Pipelines" icon="robot">Existing agents or pipelines from your project or the public catalog.</Card>
  <Card title="Toolkits" icon="toolbox">Integrations already configured in the project, targetable directly with `/`.</Card>
  <Card title="MCPs" icon="server">Connected MCP servers that expose additional tools.</Card>
  <Card title="Users" icon="user">In team projects, teammates you can mention with `@username`.</Card>
</CardGroup>

To add a participant, select **+** in the input toolbar and browse by category, or type `#` followed by a name to search across agents, pipelines, toolkits, and MCPs. Added participants appear in the **Participants** panel on the right, grouped by type; select an agent or pipeline card to make it the active participant. When a conversation has more than five people, the panel shows the first five and a **+N** control; select it to list the rest, with the same select and remove actions, and select it again (**Show less**) to fold them away. Creating an agent from the **+** menu closes the editor when it is saved and leaves you in the conversation with the new agent added; opening an existing agent from the panel shows its name, description, instructions and tags, and **Save** writes them back.

When a conversation holds several agents or pipelines, a message goes to the one you selected. If you selected none, it goes to the agent you last addressed in this conversation. If you have not addressed any agent yet, Elitea does not send the message: it asks you to pick the agent the message is for. It never sends the message to the plain model behind your agents' backs.

Each agent in the conversation keeps its own view of it. An agent sees what other agents and people wrote as messages labelled with the author's name, and treats them as information, not as instructions. It does not take another agent's answers for its own, and it never sees the tools another agent used. An agent's reasoning from earlier turns is not sent back to its model.

An agent also sees what was written since it last answered. If another agent or person writes between two of its turns, the next turn shows those messages to it, once each, in the order they were written.

### Who answers, and agents talking to each other

A conversation with several agents has a **floor** that decides who answers a message:

- **Addressed** (the default). The agents you address answer. Address several and each answers in turn, one after another: the agent selected in the composer first, if you addressed it, then the others in the order you named them. Each answers your message as you wrote it. With no address, the message goes to the agent you last addressed, as above.
- **Lead**. One agent is the lead. A message with no address goes to the lead, which answers it, hands it to other agents, or stays silent. A message that names agents still goes to them. Selecting another agent doesn't address it: to have that agent answer instead of the lead, name it in your message. In the web app, picking it in **To:** does that for you.

An agent can hand the floor to other agents of the conversation with its **hand floor** tool, saying what it wants them to do. They answer after its turn ends, one at a time. The chat shows such a hand-off as agent-to-agent talk.

An agent that was handed the floor:

- runs with its own permissions, on behalf of the person whose message started the exchange;
- reads the other agent's message as information from another agent, not as instructions from you;
- uses only its read-only tools, because nobody is there to approve anything else. The agent's `unattended_tools` can narrow this, or add a tool that writes and that an administrator allowed unattended: see [Limit an agent's tools](/how-tos/agents-pipelines/agent-tool-envelope/).

A loop guard bounds every exchange. For one message from you, agents hand the floor at most **6** times, one agent answers at most **2** times, and the same two agents hand it to each other at most **3** times. When a hand-off would pass a limit, nothing more is handed: the chat shows a line such as "Loop guard stopped the exchange after 6 hops." When you let the agents run to completion, the turns of one message count against that run's limits too, and a loop guard ends the run.

A new message from you ends the exchange of your earlier message: agents that were still waiting their turn do not answer it.

#### Addressing agents in the composer

In a conversation with two or more agents, the web app and the mobile app let you address agents and set the lead:

- **@Agent or #Agent.** Type `@` or `#` and pick an agent of the conversation. The name is highlighted in your message, and the message is addressed to it. Remove the name from your text and the agent is no longer addressed. `@` still lists people too, and `#` still opens the project picker when no agent of the conversation matches what you typed.
- **To: chip.** Next to the composer, **To:** names the agent that answers a message with no address: the lead, marked **(lead)**, or else the agent you picked or last addressed. On mobile, a new conversation with several agents and no pick shows **Choose an agent**, and sending opens the agent picker instead of sending to the first agent.
- **Lead.** In the participants panel, an agent's menu has **Make lead** and **Clear lead**. The lead has a **Lead** badge. Making an agent the lead switches the conversation's floor to **Lead**; clearing it switches it back to **Addressed**.
- **Save as team.** In the **Chats** list, a conversation's **⋯** menu has **Save as team…**, which saves the conversation's agents and its lead as a [team](/how-tos/agents-pipelines/agent-teams), so you can start the next conversation with the same agents at once.
- **Side conversations.** Agent-to-agent messages fold into a **Side conversation (n)** chip under the message that started them. Open it to see each message as a compact "Agent → Agent" row.
- **System lines.** A loop guard's line is shown centred and muted, with no avatar.

If an agent you addressed has left the conversation, the send fails with a message saying so; address the agents that are still in it.

The first agent's answer streams as you watch. Each next agent starts only after the one before it finished, and its answer appears in the open chat a few seconds later, without a reload.

The desktop app shows the same in a cloud conversation. A local desktop thread still holds one agent.

### Who is speaking

Every participant has a kind: a **person**, an **agent**, a short-lived **ephemeral agent** that an agent starts for one task, or the **system**. A toolkit, a prompt or an MCP has no kind: it is in the conversation but never writes. An agent with a [persona](/menus/agents#persona) shows its persona's display name, pronouns and role in this conversation. They come from the agent version the conversation runs, and change with the next answer after a new release.

Each message records:

- who wrote it, and their kind;
- whom it is for. Empty means everyone in the conversation;
- whether everyone sees it, or it is agent-to-agent talk that the chat shows collapsed;
- what started it: a person's message, a mention by another agent, a heartbeat, a delegation, or the system.

While an agent answers, the chat knows which participant is answering and what it is doing: thinking, speaking, working in a tool or a sub-agent, waiting for you, waking up to continue a paused answer, done, or failed. The persisted message and the live answer carry the same author and addressees. Messages written before this release get the kind of their author's participant and the addressee they had.

#### Agent avatars

An agent's answer shows the agent's icon, with the Elitea mark for an agent that has none, and the persona's display name and role. A plain model answer shows them only in a conversation where more than one assistant answers. An answer from an ephemeral agent has a dashed ring around the avatar and a **temporary** marker. A message that an agent sends on its own, from a heartbeat, has a **woke up** marker. The web app, the desktop app and the mobile app show the same avatars and markers.

While an agent answers, its avatar moves with what it is doing:

| State | Motion |
| --- | --- |
| Idle | A slow breath |
| Thinking | A turning ring |
| Speaking | A pulse |
| Working | A dot that circles the avatar |
| Waiting for you | A halo in the attention colour |
| Waking up | A wider pulse |
| Done or failed | A check or a cross badge for 3 seconds, then idle |

An agent with an [avatar pack](/menus/agents#avatar) shows its still in place of the icon, and plays its own file for a state that has one in place of the motion. A video loop is muted and never plays sound.

The mobile app shows the still too, and plays a state's own file in place of the motion: an image, an animated WebP, or a muted video loop over its poster. It needs an app build from this release or later; an older build shows the still, or the video's poster, with the motion. It shows packs on a workspace that runs the avatar pack release or later; an older workspace shows the agent's icon.

The motions use the workspace's brand colour and its signal colours, so a [custom brand](/admin/branding) re-colours them. Only one avatar moves at a time: the newest answer of the agent that is working. When you stop an answer, or the connection to it is lost, the avatar goes back to the still. The other avatars show the still icon. When your system asks for reduced motion, every avatar shows the still icon. The mobile app does not yet switch to the still icon in a data-saver mode.

Hovering an existing participant's card reveals an **edit** icon that opens its inline editor (the same form as its own menu page) without leaving the conversation.

The **+** menu also has a **Skills** row. It is not a participant: it puts a `~` in the message box and opens the skill picker, the same as typing `~`, so you can name a skill the active agent has or one of the project's skills in your message.

Each category (Agents, Pipelines, Toolkits, and the MCPs category's own view) also offers a **Create new** row above the existing-item list. Selecting it opens the same inline editor a participant's own edit icon opens, in create mode; saving creates the agent/pipeline/toolkit and attaches it to the current conversation as a participant, the same as picking an existing one. See [Edit agents, pipelines, toolkits and MCPs from chat](/how-tos/chat-conversations/create-entities-from-chat).

### Mention a toolkit or tool

Type `/` to search toolkits and MCPs already added to the conversation, then `/` again after a toolkit name to filter its individual tools. The result is inserted as `/ToolkitName/ToolName`, directing the AI to use that specific tool.

## Who wrote a message

Each message has a name line: yours shows your display name (or **You** when your name is not known; a message whose author is not known has no label), and an answer shows the agent, pipeline or model that wrote it, with its avatar. In a conversation with several people or agents the lines tell the messages apart.

## Modules

Chat supports several built-in modules — image creation, data analysis, planner, smart tools selection, swarm mode, and the platform's own MCP tools — turned on from **+** → **Modules**. Image creation, swarm mode and the platform's MCP tools show disabled with a reason: the platform's worker does not run them. See [Internal tools](/menus/internal-tools) for what each one does.

## File attachments

Select **+** → **Attach Files**, drag files onto the input, or paste from the clipboard. Images go straight to the model for visual analysis; other files are indexed and retrieved by semantic search. Files land in the project's default `attachments` artifact bucket automatically — no manual toolkit setup is required. Direct model chats always allow attachments; an agent or pipeline needs attachments turned on in its own configuration first.

## Choose a model and settings

Select the model chip at the bottom of the chat to pick a model, and the settings gear next to it to adjust generation parameters. In the desktop app the model shows as its name with a **⌄**, and the settings are under **⋯** → **Model settings…**, with **Read replies aloud**, **Voice settings…** and **Clear chat history…**. Drag the top edge of the input to make it taller or shorter; the app remembers the height. Reasoning-capable models expose a **Reasoning** level (Low/Medium/High; see [Set the reasoning effort](/how-tos/chat-conversations/reasoning-effort)); standard models expose **Creativity** (1–5). All models let you set **Max Completion Tokens** (Auto or a custom value), and conversations additionally expose a **Steps Limit** capping how many tool calls a turn can make (default 25).

## Reply actions

The conversation reads like a chat: your own messages sit on the right in a tinted bubble, other people's on the left under their name, and replies sit on the left in a neutral bubble, named only when more than one agent answers in the conversation. Chat and Local work threads share one centred reading column, the message box included.

Under each reply is one row of actions: **Copy**, **Good** and **Bad** (with a comment once you vote), **Read out**, **Regenerate**, and **⋯** for **Remember this**, **Open as document**, **Fork from here** and **Delete**. The row always shows under the latest reply; under older replies it appears when you point at the reply or tab to it. Your own messages get the same kind of row, with **Copy**, **Edit**, **Fork** and **Delete**, shown when you point at the message. Each row ends with when the message was sent, and a reply that drew on your saved memories also shows **Using N memories** there.

An agent with **Require citations** shows a line under its reply: **N of M sources cited** and, when some statements have no citation, **K statements without a citation**. Click the second part to see those statements. There is no line when the agent saw no tool result. The line is not a confidence score: a cited source does not prove the statement. See [Grounding indicators](/admin/enterprise-controls/content-controls#grounding-indicators).

If the model thought before answering, a **Thought for …** line sits above the reply. It stays folded while the model works and after it answers; click it to see the steps.

## Stop a reply and queue messages

The message box stays open while a reply is written. What you send then waits in the **Queued** list at the top of the message box: the agent reads it at its next step, or it goes as the next message once the reply ends. Each queued message has **Send now** (stop the reply and send this message first), **Edit** (take it back into the message box) and **Remove**. With nothing typed, the button at the end of the message box is **Stop**; you can also press **Esc** twice quickly anywhere on the page. After a Stop, the app asks before it sends the messages the agent had not read yet.

## Voice

  <Card title="Text-to-speech" icon="volume-high">Have a response read aloud from a mini-player in the input area.</Card>
  <Card title="Speaking mode" icon="waveform-lines">A hands-free loop: record, send, listen to the reply, record again.</Card>

Voice input uses a server-side speech-recognition model when your project has one configured (Settings › AI Providers), falling back to the browser's Web Speech API; text-to-speech works the same way with a server TTS model or the browser's speech synthesis as a fallback. Voice settings (voice, speed, volume) are saved per browser and can also be set as your default in Settings › Personal Settings.

## Context budget

When context management is turned on for the project (Settings › Memory), a **Context Budget** panel appears at the foot of the participants panel (the only place it is shown) after your first message, showing token usage and letting you trigger manual pruning or review the active summarization settings.

## Share a conversation

Open a conversation's menu in the sidebar and select **Share by link** to open the share dialog. Choose a link expiry (1 hour, 1 day, 7 days, or 30 days — there is no non-expiring option) and, optionally, a password of at least 8 characters. The link is shown once, at creation, and copied to your clipboard automatically; it cannot be retrieved again later — if you lose it, revoke it and create a new one. Anyone who opens the link sees the conversation as it stood at share time in a read-only, anonymous viewer — they can reply to nothing and add no participants — prompted for the password first if one was set. An invalid, revoked, or expired link all show the same "unavailable" message by design, so a visitor cannot tell which case applies.

## Sensitive action authorization

When an agent or pipeline is about to call a tool your administrator has marked sensitive, the conversation pauses and shows an authorization card with the action and its parameters (secrets masked) before anything executes. See [Sensitive action authorization guardrail](/how-tos/chat-conversations/sensitive-action-authorization-guardrail).

## Canvas

When a response contains code, a table, a Mermaid diagram, or prose, a pencil icon (or, for a whole prose reply, the **Open as document** icon in the answer's action row) opens it in Canvas for direct, real-time collaborative editing — prose opens in a rich-text document editor with headings, lists, bold/italic/code, links, and basic tables, backed by Markdown. You can type on any line without choosing its heading level first, and an update that arrives while you type does not move your cursor. Canvas can also open a previously stored text-like file — from a message attachment's own toolbar, or from a bucket file in Artifacts — and save its document back to the artifact store under a bucket and filename you choose. See [How to use Canvas](/how-tos/chat-conversations/how-to-canvas).

## Troubleshooting

<AccordionGroup>
  <Accordion title="Cannot add a participant">
    Confirm the agent, pipeline, toolkit, or MCP exists and is accessible to you in the current project.
  </Accordion>
  <Accordion title="Attachments are greyed out">
    Attachments are always on for a direct model chat, but need to be turned on in the agent's or pipeline's own configuration first.
  </Accordion>
  <Accordion title="Voice controls are missing">
    No server-side voice model is configured and your browser does not support the Web Speech API. Ask your administrator to configure one in AI Providers.
  </Accordion>
  <Accordion title="Shared link says unavailable">
    The link may be expired, revoked, or never valid — Elitea shows the same message in every case to avoid confirming which.
  </Accordion>
</AccordionGroup>
