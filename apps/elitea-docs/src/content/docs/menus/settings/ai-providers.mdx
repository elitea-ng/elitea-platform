AI Providers is where a project registers the models and storage it uses, and picks defaults for each category. Settings here apply at the project level for every member.

## Categories

<CardGroup cols={3}>
  <Card title="LLMs" icon="brain">Language models, with Default, High-tier, and Low-tier selections.</Card>
  <Card title="Embedding Models" icon="database">Used for indexing and semantic search.</Card>
  <Card title="Image Generation" icon="image">Powers the Image creation module in chat.</Card>
  <Card title="Speech Recognition (ASR)" icon="microphone-lines">Server-side voice input.</Card>
  <Card title="Text to Speech (TTS)" icon="volume-high">Server-side spoken playback.</Card>

Each category shows its configured models as cards with a provider icon, name, and a badge for Default, High-tier, or Low-tier. Select a card to edit it, if your role allows.

## Add a model or credential

<Steps>
  <Step title="Create AI Credentials first">Choose a provider — OpenAI, Azure OpenAI, Anthropic, Amazon Bedrock, Google Vertex AI, Ollama, vLLM, or EPAM AI Dial — and provide its endpoint and key. One credential can back several models.</Step>
  <Step title="Add the model">Select **+**, choose the model category, and fill in a display name, the exact provider model identifier, and — for LLMs — context window, max output tokens, and whether it supports reasoning or vision.</Step>
  <Step title="Set as default">Use the category's dropdowns to make the new configuration the project default, or the high-tier / low-tier choice.</Step>
</Steps>

<Warning title="Model name must match the provider exactly">
The **Name** field must be the provider's own model identifier (or Azure deployment name) — not a display label. Refer to your provider's model list if a connection or generation fails.
</Warning>

<Warning title="AI Dial and reasoning models">
When an OpenAI or Anthropic model configuration uses AI Dial credentials, leave **Supports Reasoning** off — turning it on breaks connection validation for that combination.
</Warning>

## Reasoning control of a model

A reasoning model has one of five control forms. The form tells the runtime how to switch thinking on or off and how to set its level. The runtime uses it for the [reasoning effort](/how-tos/chat-conversations/reasoning-effort) of each agent and chat.

| Form | What the runtime sends | Typical models |
| --- | --- | --- |
| `effort` | `reasoning_effort`: none, low, medium or high | OpenAI gpt-5.1 and later |
| `budget` | A thinking budget for each level, or adaptive thinking where the model has it | Claude, Gemini 2.5 Flash |
| `toggle` | `chat_template_kwargs.enable_thinking` | Qwen3 and later on vLLM or SGLang |
| `fixed_on` | Nothing. The model always thinks. | QwQ, DeepSeek R1, Qwen thinking models, Gemini Pro |
| `fixed_off` | Nothing. The model cannot think. | |

The platform has family defaults for these forms. A default applies only to a model with **Supports Reasoning** on. To set the form of one model, add these keys to the model's `data` with the configurations API. The form on this page has no fields for them yet.

- `reasoning_control`: one of the five forms.
- `reasoning_tool_steps`: `true` to keep thinking on routine tool steps when the setting is Auto. Set it for a model that fails or degrades when thinking changes inside one tool loop. Claude and Gemini have it by default. A `budget` model keeps one thinking state for the whole tool loop in any case, so a save refuses `false` together with `budget`.
- `reasoning_off_with_tools`: `true` for a model that refuses thinking beside tools. On a request that carries tools, Auto (or no setting) then sends the off form on every step. A request without tools still thinks, and a level that the user chose is sent as chosen. OpenAI GPT-5.6 has it by default.

The keys of the model win over the family default. The model catalogue returns the result as `reasoning_control`, `reasoning_tool_steps` and `reasoning_off_with_tools`.

A model with no form keeps the form of earlier releases: a thinking budget on the native Anthropic API, `reasoning_effort` on every other API. For such a model, Auto thinks at the medium level on every step. The runtime does not send the off form, because some models (the OpenAI o-series) refuse it.

<Warning title="Rules on save">
- A save refuses a `reasoning_control` that is not one of the five forms.
- A save refuses a form other than `fixed_off` on a model with **Supports Reasoning** off.
- A save refuses `reasoning_tool_steps: false` on a `budget` model.
- After you change the form, an agent, toolkit or chat that has **Off** on a `fixed_on` model, or a level on a `fixed_off` model, runs as **Auto**, and the platform logs a warning. Change the stored reasoning setting to a value the model accepts.
</Warning>

An operator changes the family defaults with SQL in the `elitea_runtime.model_reasoning_defaults` table. An upgrade does not overwrite a row that you changed.

## Speech recognition and text-to-speech fallbacks

If no ASR model is configured, voice input falls back to the browser's Web Speech API; if no TTS model is configured, playback falls back to the browser's SpeechSynthesis API. Elitea determines ASR mode from the model name — `whisper` or `transcribe` selects batch transcription; anything else uses realtime streaming.

## Troubleshooting

<AccordionGroup>
  <Accordion title="No access to LLM / model not found">Confirm the model name matches the provider's identifier exactly and that your credential has access to it.</Accordion>
  <Accordion title="Authentication failed (401/403)">Recheck the API key or token for typos or expiry, and confirm the endpoint URL is correct for your provider.</Accordion>
  <Accordion title="Voice falls back to the browser voice unexpectedly">Confirm a default ASR or TTS model is actually selected in this page, not just configured.</Accordion>
</AccordionGroup>
