title: "Skills"
description: "Create reusable, Markdown-based instruction sets you attach to agents and invoke on demand during a conversation."

A skill is a focused, reusable instruction set — write it once in Markdown, attach it to as many agents as you need, and invoke it mid-conversation with `~skill-name`. Skills are available in team and personal projects only; the Skills menu is hidden when the Public project is selected.

<Screenshot id="skills-list" alt="The Skills dashboard for the current project" />

The Skills page has two modes, switched at the top of the **List** tab in the side panel: **Skills** (the project's own skills) and **Public** (the published catalog). The **List** tab holds the search, **+ New skill**, **Import**, sort, the card/table switch, folders and the tag filter; see [Page layout](/menus/page-layout).

## Create a skill

<Steps>
  <Step title="Open the form">Select **+ New skill** in the **List** tab (or in the bar above the list when the side panel is closed), or the **+** next to **Skills** in the sidebar.</Step>
  <Step title="Fill in General">Give it a **Name** (lowercase letters, digits, and hyphens only, no leading/trailing hyphen, 64 characters max, and it must not contain "claude" or "anthropic"), a **Description**, and optional tags.</Step>
  <Step title="Write Instructions">Enter the skill's instructions in the Markdown editor, up to 5,000 characters. Toggle Edit/Preview to check formatting.</Step>
  <Step title="Save">Select **Test skill** to open a chat with the skill pinned and check its behavior before attaching it to any agent.</Step>
</Steps>

<Tip title="Generate a skill with AI">
Select **Generate with AI** in the General section to describe what the skill should do in plain language and get a drafted name, description, and instructions to review before saving.
</Tip>

## Try a skill

A skill is text that an agent or a model loads, so it is tried in a chat, not run on its own. **Try it** opens a new conversation on your project's default model, with no tools, and the skill pinned to it. The first message just works; a model or an agent you add later answers with the skill too. The chat is named `Try: ` followed by the skill's name and is an ordinary conversation, so it keeps its history.

**Try it** is on a Marketplace skill listing and on its card, in the row menu of your own skills, and in the skill editor, where it reads **Test skill**. While the editor holds unsaved edits it says **Save to try** and is off, because the chat uses the saved text. The chat pins the skill, not a named version of it, so it uses the skill as it is saved. A listing is pinned by reference, so nothing is added to your project, and the listing page says its text is another project's until you add it and trust it.

Two more actions put a skill in a conversation you already have:

- **Use in a chat** (a listing page, or a skill's row menu) pins the skill to a new chat or to a conversation you pick. A listing is pinned by reference, so nothing is forked.
- **Add to a conversation** (a listing page, needs the fork permission) copies the listing version into your project and pins that copy to the conversation you pick.

A conversation holds at most five skills. In the desktop app a local thread pins one of your project’s skills from its `/` menu, and both actions above work on a local thread: a Marketplace listing is copied into your project first, and the copy is pinned. See [Skills in a conversation](/menus/chat#skills-in-a-conversation).

## Versions

Skills keep a version history, the same **base**-plus-named-versions model [agents and pipelines](/how-tos/agents-pipelines/entity-versioning) use:

<Steps>
<Step title="Work in base">
Every new skill starts on the **base** version. Edit and save it as many times as you like.
</Step>
<Step title="Save as a new version">
Click **New version** and give it a name. `base` is reserved and cannot be reused as a custom name; a duplicate name is rejected.
</Step>
<Step title="Switch and edit">
Use the version dropdown next to the skill's name to switch versions. Saving always updates whichever version is currently selected.
</Step>
</Steps>

**Set default** pins a version as the one a new attachment to an agent proposes — it does not change what an agent that has *already* attached this skill uses; that stays fixed at attach time (see [Attach a skill to an agent](#attach-a-skill-to-an-agent) below). You cannot delete the default version or `base`, and a published version is frozen until you unpublish it.

**Compare versions** opens a read-only, side-by-side diff of the current version's instructions and tags against any other version — useful for checking what changed before you restore or publish.

**Restore** copies a named version's instructions and tags back onto `base`, overwriting `base`'s current content. This is the skill equivalent of agents' "Set as default": skills have no separate "currently active" pointer to repoint, so restoring means writing the content directly onto the one version the unversioned editor and every new attachment read.

**Delete version** removes any version except `base`, the current default, or a published one.

## Export, import, fork, and publish

- **Export** downloads the current version as a `.md` file; **Import** in the **List** tab uploads one back (always as a new `base` version, regardless of the version it was exported from).
- **Fork** copies a skill version into a project you choose.
- **Publish** submits a version to the [Marketplace](/menus/marketplace); **Unpublish** removes it. See [Skill publishing](/how-tos/agents-pipelines/publishing).

## Attach a skill to an agent

Open the agent, scroll to its **Skills** section, and select **+ Skill** to search and attach — up to five skills per agent version. Each attachment uses the skill's `base` version by default; select the version name on the card to switch. Attaching requires the agent to be saved first.

## Use a skill in chat

In a conversation, type `~` or `/skill` to open a picker of the skills you can use, then select one to invoke its instructions for that turn. The skills pinned to the conversation come first. Both ways write the same `~name` into your message, so `~` stays as it was. A chat with only a model takes project skills too. On an agent chat the picker also lists the agent's own skills. A skill from another project that your project has not trusted carries an **Untrusted** badge, and a pinned one carries **Pinned**. **Pin to this conversation** on a row pins that skill without picking it for the message. The `/` list starts with a **Skills** entry (on the web and desktop apps, and on mobile): choose it, or type `/skill`, and the skills pinned to the conversation come first. The **Untrusted** badge comes with the skills list itself, so it shows at once on every app, mobile included, even for a skill that is not pinned.

### Skills from another project are untrusted until you trust them

A skill from another project shows a note in its editor. Read the text, then choose **Trust this version for this project**; **Revoke trust** undoes it. Trust is recorded and audited, needs the right to edit skills, and covers that exact version only.

A skill you add from the Marketplace is text another project wrote. When you pick one in a chat, the model gets its text as quoted data, not as an instruction of your project, until your project has trusted that exact version of the text. Any change to the text, for example a newer version pulled from the Marketplace, is a new version and is untrusted again. A skill you made yourself, imported, or published from your project is never untrusted, and neither is a skill attached to an agent: attaching is part of the agent's own review. Skills that existed before this rule keep working as before. A model chat that has only a model, with no agent, takes picked skills too; the server accepts them in `payload.skills` of the message start, in the same shape an agent chat sends, up to five skills and 64 KiB of text together.

An administrator can also trust a whole publisher: in **Features › Skill Publishing**, **Trusted Skill Publishers** lists project ids whose skills every project treats as trusted. A skill added from one of those projects is applied as an instruction with no review, and its editor says so instead of offering **Trust this version**. Use it for your organization's own skill library only, because a later edit by that publisher takes effect without anyone reading it. Removing a project from the list puts its skills back to quoted data.

The **Skills** list marks a skill from another project that your project has not trusted with an **Untrusted** badge.

A conversation's pinned skills are read again when a message starts. If a message is sent again after a network failure and a skill was unpinned in between, or you lost the right to read it, the retry is refused the same way a pick of that skill is. Send the message again with the pin in place, or without it.

## Delete a skill

Deleting a skill removes it from every agent it is attached to. Confirm in the dialog — unlike the agent editor's delete confirmation, it does not ask you to type the skill's name.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Skills menu is missing">You are in the Public project — switch to a team or personal project.</Accordion>
  <Accordion title="Cannot save">Check the character limits and validation rules on Name, Description, and Instructions, and confirm something actually changed since the last save.</Accordion>
  <Accordion title="+ Skill button is disabled on an agent">Save the agent first, or check whether it already has five skills attached.</Accordion>
  <Accordion title="~ mention shows no skills">The current agent has no skills attached yet — attach one and start a new conversation.</Accordion>
</AccordionGroup>
