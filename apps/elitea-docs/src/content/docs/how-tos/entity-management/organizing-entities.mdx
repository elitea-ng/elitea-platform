As a project accumulates agents, pipelines, toolkits, credentials, and MCP connections, four features keep the catalogue navigable: search, tags, pins, and folders.

## Search

The Agents, Pipelines, Toolkits, Credentials, and MCPs pages each have a search box that matches on name and description, and lets you filter by tag. Type into the box to see matching results grouped by tag and by entity type; select a result to open it directly.

<Screenshot id="entities-search-and-tags" alt="Agents list with the search box open and tag chips visible" />

## Tags

Tags are free-form labels you attach to an entity to group it by topic, team, or project. Add one from the entity's configuration:

<Steps>
1. Open the entity's configuration.
2. Find the **Tags** field and start typing.
3. Select a suggested tag or press Enter to create a new one.
4. Save the entity.
</Steps>

Tags are shared within a project — anyone with search access can filter by them, which is what makes them useful for grouping work across a team.

## Pins

Pinning keeps an entity at the top of its list, across sessions, so you don't have to scroll or search for something you use constantly. Pin and unpin with a single click from an entity's list row; pinning works for agents, pipelines, toolkits, credentials, and MCPs.

## Folders

Two kinds of folders exist, and they work differently.

**Chat folders** group conversations in the chat sidebar. Create a folder from the conversation list, then drag conversations into it, or move a conversation into a folder from its context menu.

<Screenshot id="chat-sidebar-folder" alt="Chat sidebar showing a folder containing conversations" />

**Project folders** group the items of the **Agents**, **Pipelines**, **Skills**, **Toolkits & Indexes** and **MCPs** lists. Each list has its own folders, a folder holds items of that list only, and an item is in one folder at a time. They belong to the project, not to you: every member sees the same folders and the same contents, like the items themselves. They appear in your project's own lists, not in the public tabs or the Public project.

<Steps>
1. Open the list (for example **Agents**) and select **Filters** in the toolbar. The **Folders** section is at the top of the panel.
2. Select **+** (**New folder**), type a name and select **Create**. A name is unique within its list, ignoring upper and lower case; a second **Reports** is refused with a message.
3. Put an item in a folder: select the folder icon on its card (or in the **Folder** column of the table view), then choose the folder. Choose **Remove from folder** in the same menu to take it out.
4. Select a folder in the **Folders** section to show only its items, and **All** to show everything again. The open folder is kept in the page address, so a link to the filtered list works.
</Steps>

A folder's **⋯** menu has **Rename**, **Move up**, **Move down** and **Delete…**. The folders are listed in the order you set, and a new folder goes to the top. **Delete…** removes the folder only: its items go back to the list and nothing else is deleted.

What you can do follows the permissions you already have for that list. Anyone who can list the items sees the folders. Creating a folder needs the list's create permission (for example, create agents). Renaming, reordering and deleting folders and moving an item into one need the list's update permission (for example, update agents). Without them you see the folders and the **Folder** column and no controls. There is no separate folder permission.

The **Skills**, **Toolkits & Indexes** and **MCPs** lists load more rows as you scroll; with a folder open, the page loads the remaining rows so the folder shows all of its items. The mobile app has no project lists, so it has no project folders; the desktop app has them, exactly as the browser does.
