As a project accumulates agents, pipelines, toolkits, credentials, and MCP connections, four features keep the catalogue navigable: search, tags, pins, and folders.

## Search

The Agents, Pipelines, Toolkits, Credentials, and MCPs pages each have a search box that matches on name and description, and lets you filter by tag. Type into the box to see matching results grouped by tag and by entity type; select a result to open it directly.

<Screenshot id="entities-search-and-tags" alt="Agents list with the search box open and tag chips visible" />

## Tags

Tags are free-form labels you attach to an entity to group it by topic, team, or project. Add one from the entity's configuration:

<Steps>
1. Open the entity's configuration.
2. Find the **Tags** field and start typing.
3. Select a suggested tag or press Enter to create a new one.
4. Save the entity.
</Steps>

Tags are shared within a project — anyone with search access can filter by them, which is what makes them useful for grouping work across a team.

## Pins

On the **Agents**, **Pipelines**, **Skills**, **Toolkits & Indexes** and **MCPs** lists a pin is yours alone; see [Your Pinned group](#your-pinned-group) below. Elsewhere, pinning keeps an entity at the top of its list, across sessions, so you don't have to scroll or search for something you use constantly. Pin and unpin with a single click from an entity's list row; pinning works for agents, pipelines, toolkits, credentials, and MCPs.

## Folders

Two kinds of folders exist, and they work differently.

**Chat folders** group conversations in the chat sidebar. Create a folder from the conversation list, then drag conversations into it, or move a conversation into a folder from its context menu.

<Screenshot id="chat-sidebar-folder" alt="Chat sidebar showing a folder containing conversations" />

**Project folders** group the items of the **Agents**, **Pipelines**, **Skills**, **Toolkits & Indexes** and **MCPs** lists. Each list has its own folders, a folder holds items of that list only, and an item is in one folder at a time. They belong to the project, not to you: every member sees the same folders and the same contents, like the items themselves. They appear in your project's own lists, not in the public tabs or the Public project.

<Steps>
1. Open the list (for example **Agents**). The **List** tab of the side panel is open on a wide window; if it is closed, select the side panel toggle at the right end of the title bar. The **Folders** section is in that tab.
2. Select **+** (**New folder**), type a name and select **Create**. A name is unique within its list, ignoring upper and lower case; a second **Reports** is refused with a message.
3. Put an item in a folder: select the folder icon on its card (or in the **Folder** column of the table view), then choose the folder. Choose **Remove from folder** in the same menu to take it out.
4. Select a folder in the **Folders** section to show only its items, and **All** to show everything again. The open folder is kept in the page address, so a link to the filtered list works.
</Steps>

### Drag and drop, keyboard and Move to folder

Each card and each table row has a grip. Drag it onto a folder in the **Folders** section to put the item there, onto another folder to move it, or onto the **Drop here to take it out of its folder** area that appears while you drag an item that is in a folder. Drag one of several selected items and all of them go together.

To do the same from the keyboard, press **Tab** to the grip (it is named *Drag \<name\> to a folder*), press **Space** to pick the item up, use the **arrow keys** to move to a folder, and press **Space** to drop it; **Escape** cancels. A screen reader says each step (*Picked up Reviewer*, *Reviewer is over Support*, *Reviewer dropped on Support*) and, once the server has answered, *Moved Reviewer to Support*. You never have to drag: the folder icon on a card or row (**Move to folder**), and **Move to folder** in the selection section of the side panel (select several items first), give the same result. The selection's **Move to folder** moves every selected item, and keeps only the ones the server refused selected.

An item you move into a folder lands at the top of it.

### Order inside a folder

On the **Agents** and **Pipelines** lists, an open folder is sorted by **Folder order** (the first choice of the **Sort** list, and the default there): the order the project keeps for that folder, the same for every member. Drag a card or row by its grip onto another one to put it in that place; the list shows the new order at once and goes back to the old one, with a message, if the server refuses it. From the keyboard, pick the grip up with **Space**, move with the **arrow keys** (a screen reader says *Reviewer is over position 2 of 5*), and drop with **Space**; dropping on a folder still moves the item there. The folder icon's menu also has **Move up** and **Move down**, and a screen reader hears *Moved Reviewer to position 2 of 5*. Choose **Created** or **Name** in **Sort** to see the folder in that order instead; dragging then only moves items between folders. Reordering needs the same update permission as moving an item into a folder.

Moving an item is recorded in the audit trail with the item and the folder, because anyone with update rights can move another member's item.

### Your Pinned group

Select the pin on a card or row to add the item to your **Pinned** group, and select **Pinned** at the top of the **Folders** section to show only what you pinned (with how many). Pins are private: other members do not see yours, and you need only the right to list the items, not to update them. Unlike a folder, a pin does not take the item out of its folder.

A folder's **⋯** menu has **Rename**, **Move up**, **Move down** and **Delete…**. The folders are listed in the order you set, and a new folder goes to the top. **Delete…** removes the folder only: its items go back to the list and nothing else is deleted.

What you can do follows the permissions you already have for that list. Anyone who can list the items sees the folders. Creating a folder needs the list's create permission (for example, create agents). Renaming, reordering and deleting folders and moving an item into one need the list's update permission (for example, update agents). Without them you see the folders and the **Folder** column and no controls. There is no separate folder permission.

The **Skills**, **Toolkits & Indexes** and **MCPs** lists load more rows as you scroll; with a folder open, the page loads the remaining rows so the folder shows all of its items. The mobile app has no Agents, Pipelines, Skills, Toolkits or MCPs management lists (it chats with the items you already have), so it has no project folders or pins; the desktop app is the browser build and has all of the above, exactly as the browser does.
