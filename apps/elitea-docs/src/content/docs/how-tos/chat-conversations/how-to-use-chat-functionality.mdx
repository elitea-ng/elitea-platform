Chat is where you talk to models, agents, pipelines, toolkits, and MCP servers in one conversation. Every conversation keeps its own context — nothing is shared between conversations unless you attach the same participant to more than one.

## Create a conversation

Click **+ Conversation** at the top of the sidebar. Pick a model from the selector at the bottom of the composer, or type `#` to search and attach an agent, pipeline, toolkit, or MCP connection that already exists in the project — selected participants appear as chips above the input box. Type your message and send it; the conversation is named automatically from your first message, and you can rename it any time.

## Organize conversations into folders

Click the folder icon next to **Conversations** at the top of the sidebar to create a folder, then move conversations into it either by dragging one onto the folder, or by right-clicking a conversation and choosing **Move to**.

<Steps>
<Step title="Manage a conversation">
Right-click a conversation (or use its options menu) for: **Rename**, **Move to**, **Playback** (step through it turn by turn without sending anything live), **Pin/unpin** (keeps it at the top of the list), and **Delete**.
</Step>
<Step title="Manage a folder">
Right-click a folder for: **Rename**, **Pin/unpin**, and **Delete** — deleting a folder does not delete the conversations in it, they move back to the root list.
</Step>
</Steps>

## Visibility in private vs. team projects

<Tabs>
<Tab title="Private project">
Conversations and folders are personal — only you can see them. You can still add agents, pipelines, toolkits and MCPs as participants, but you cannot add other users.
</Tab>
<Tab title="Team project">
Folders are visible to every project member. A conversation is visible only to its participants, unless it's explicitly marked public — at which point every project member can see and interact with it.

<Warning>
Making a conversation or folder public cannot be undone.
</Warning>
</Tab>
</Tabs>

In a team project, add a colleague as a conversation participant to collaborate directly — see [Add teammates to a conversation](/how-tos/chat-conversations/add-teammates-to-conversation).

## Attach participants

Click the **+** icon in the composer toolbar to open the menu: **Modules** (the internal tools, listed first), then **Agents**, **Pipelines**, **Toolkits**, and **MCPs**. Each category lists the items that already exist in the project — pick one to add it as a participant. **Agents**, **Pipelines**, and **Toolkits** (which also covers MCP connections) also show a **Create new** row above the list — see [Create and edit agents, pipelines, toolkits and MCPs from chat](/how-tos/chat-conversations/create-entities-from-chat) for the create-from-composer flow.

You can also type `#` in the message box for the same picker inline, or `/` to mention a specific tool from a toolkit or MCP that's already a participant (for example `/Jira/createIssue`). The search box in each category filters only the participants already loaded on the page — on a project with a very large catalogue, typing a name that hasn't loaded yet finds nothing.

Once a participant is attached, click it in the **Participants** panel to make it active, then send your message. To edit an attached agent, pipeline, or toolkit's configuration without leaving the conversation, see [Edit agents, pipelines, toolkits and MCPs from chat](/how-tos/chat-conversations/create-entities-from-chat).

## Choose a model and tune settings

Click the model selector to pick an LLM. Click the settings icon next to it to adjust generation parameters — the exact fields depend on the model (a reasoning depth control for reasoning models, a creativity/temperature control for standard ones), plus a max-completion-tokens option and a **Steps limit** (default 25, range 0–999) that caps how many tool calls a turn can make before the run stops and returns whatever it has.

## Work with the response

Below an assistant message you get **Read out** (if voice is configured — see [Voice](/menus/chat#voice)), **Copy**, **Regenerate**, and **Delete**. To change your own last message, use its **Edit** action: the message becomes editable, any attachments stay attached unless you remove them, and **Save and apply** re-sends it and regenerates the answer. **Regenerate** replaces the answer text in place. If the answer holds a [canvas](/how-tos/chat-conversations/how-to-canvas#regenerating-a-reply-that-holds-a-canvas), the canvas and its saved versions stay in the message.

Next to those, a thumbs-up and thumbs-down let you rate an assistant answer. Selecting one highlights it and, once you've rated a message, a comment icon appears so you can attach an optional note explaining why. Hover either thumb to see how many teammates rated the message the same way; changing your mind (clicking the other thumb, or clicking your own vote again) updates or clears your rating. A rated message keeps its feedback when the conversation is exported.

## Run unattended

Use unattended mode for a long task that must continue while you are away. You give a grant before you send. The grant tells the platform which questions it can answer for you in this task.

1. Above the message box, click **Run unattended…**.
2. Read each part of the grant and set it:
   - **Continue at the step limit**: when the run stops at its step limit, the platform starts a new turn with "Continue from where you stopped."
   - **Continue at the output limit**: when the answer stops at the output limit, the platform continues the same answer.
   - **Sensitive tools**: select the tools of the agent that can run without a pause. The list shows the tools that the agent's toolkits select. A tool that you do not select still pauses for your approval.
   - **Chain limits**: the most automatic continuations (default 20), the most spend in USD (default: the spend cap of one run × 10) and the deadline in hours (default 12). An empty field takes the platform default.
3. Click **Start**. A notice above the message box shows the grant. Click **Edit** to change it, or **Turn off** to stop unattended mode.
4. Send your message. Each message that you send in unattended mode starts a new task with its own grant.

In the conversation, each turn that the platform started for you shows **Continued automatically** with its number in the task. An answer that stopped at its step limit shows a notice. The task ends when it is complete, when it waits for a question that the grant does not answer, or when it reaches a chain limit.

The grant never lifts your organization's guardrails, budgets, run caps or kill switches. If the platform cannot accept the grant, the message is not sent, and the error names the tool and the reason. For example, a tool in a category that your administrator keeps out of grants (by default, payments) is refused. Clear that tool in the grant and send again. Administrators set the rules in [Unattended grants](/admin/enterprise-controls/runtime-safety#unattended-grants).
