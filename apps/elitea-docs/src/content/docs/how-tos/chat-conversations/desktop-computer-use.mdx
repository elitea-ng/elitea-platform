---
title: "Let the agent use your other apps (desktop)"
description: "How a Local work thread in the Elitea desktop app sees and operates your other macOS applications, what you are asked, and the limits that hold in every mode."
---

In the Elitea desktop app on macOS, the agent of a **Local work** thread can see and operate your other applications: read a window, press a button, type into a field, send a key chord, open an app. These are the `computer` tools. They are off until your organization and you both turn them on.

## Turn it on

<Steps>
1. Your organization's client policy must allow computer use (`local_work_computer_use`). If it does not, the agent has no `computer` tools, and any call is denied.
2. Turn on the device switch. In the app's `settings.json` (in the app's configuration folder), set `"computer_use": true`. It is off unless it is `true`.
3. Grant **Accessibility** to Elitea in **System Settings ▸ Privacy & Security ▸ Accessibility**. Without it the agent cannot read or operate any app.
4. To let the agent take screenshots, also grant **Screen Recording** in **System Settings ▸ Privacy & Security ▸ Screen Recording**, then restart Elitea. Without it, the screenshot and coordinate-click tools are not offered.
</Steps>

The next turn of a thread has the tools. Sub-agents never get them, and a cloud run never has them.

## What the agent can do

| Tool | What it does |
| --- | --- |
| `computer_apps` | Lists the running apps and their windows. Apps your policy denies, and Elitea itself, are left out. |
| `computer_snapshot` | Reads one window as a compact list of its controls, with refs such as `@s3:e12` the agent acts on. |
| `computer_screenshot` | Takes a picture of one window, downscaled, or of a region of it (`zoom`) at full scale. |
| `computer_act` | Presses, sets a value, focuses, selects, scrolls, expands, collapses or toggles a control. |
| `computer_type` | Types text into a control, or into the focused control of the app, which must be in front. |
| `computer_key` | Sends one key chord, such as `cmd+s`, to the app, which must be in front. |
| `computer_click_at` | Clicks a point of the window's last screenshot, for apps whose controls cannot be read. The app must be in front, and the window must not have moved since the screenshot. It moves the pointer. |
| `computer_open_app` | Launches an app, or brings it forward. |
| `computer_wait` | Waits for a window, a control state, some text, or a stable window. |
| `computer_request_user` | Hands control to you for something only you may do, such as a password or a sign-in. |

## What you are asked

The agent asks before it sees an app, and asks again, separately, before it acts in it. You can answer **Allow once**, **Allow for this thread**, or **Always for this app**. An action on a control that sends, deletes, buys, pays, signs or submits is asked every time, whatever you allowed before.

- **Plan mode.** The agent can see apps, but not act in them, until you accept the plan.
- **Bypass mode.** Bypass does not answer `computer` questions: you are still asked.
- **Unattended runs.** Every act waits for you. If nobody answers, the act is declined.
- **Hand-overs.** `computer_request_user` shows you what the agent needs. Do it, then answer **Done**, or decline. If nobody answers within 15 minutes, it is a decline.

## Limits that always hold

These hold in every mode, bypass included, and no answer lifts them:

- **Locked or sleeping screen.** No call runs while the screen is locked, the screensaver is up, the display sleeps, or another user is switched in (`screen_unavailable`).
- **Passwords.** A password field shows as `[secure]` with no value, and the agent never types into it. While macOS secure input is on (a password prompt anywhere), every act is refused (`secure_field_refused`). The agent asks you to type it instead.
- **Denied chords and menu items.** Quit, force quit, log out, lock, shut down, empty Trash, Spotlight and Siri are refused (`chord_refused`). So are the menu items Quit, Log Out, Shut Down, Restart, Sleep, Lock Screen, Force Quit and Switch User, in any app's menus and the Apple menu (`menu_item_refused`).
- **Only the app it names.** Typing with no target control, a key chord and a coordinate click go only into the app the agent named, and only while that app is in front (`not_frontmost`). A window or a control of one app is never used for another.
- **Screenshots show one window.** A screenshot, zoomed or not, shows that window only; another window on top of it does not appear.
- **Elitea itself.** The agent never reads or acts on Elitea's own windows, so it cannot approve its own questions (`own_window_refused`). A coordinate click that another window covers is refused too.
- **Denied apps.** Apps the platform or your policy denies, such as Keychain Access and the password managers, are never read or acted on.
- **Rate.** At most 10 acts and 2 screenshots in any second (`rate_limited`).

## What the agent sees

Window titles, control names and screenshots are what the screen shows, so another app can put text there. The agent treats them as untrusted content: they come back in a marked block, and the agent follows no instruction in them. Only the last three screenshots stay in the agent's context. Older ones are replaced by a short note. Text the agent types is not echoed back in the tool result.

## What is recorded

Each `computer` call is recorded with the turn, as a step record of the run: the tool, the app's bundle id, the window title, the action, the control it acted on, and the outcome (done, the refusal code, or declined). The questions you were asked and your answers go to the approval ledger with the turn.

- **Typed text.** What the agent types is recorded only as its length and a keyed digest, never as text. The key is drawn for each turn and never leaves your computer, so the digest tells two texts of one turn apart but cannot be turned back into a PIN or password. The tool row in the transcript, the thread history and the saved turn show the length and digest in its place; the agent's stored conversation on your computer keeps the length only.
- **Screenshots.** A screenshot appears in the transcript as a small thumbnail under its tool row. The saved turn records that a screenshot was taken, its size and its digest. The picture itself stays on your computer.
- **Uploading screenshots.** A project admin can turn on **Upload screenshots** for the project (the `computer_use` project setting, below). Screenshots are then also saved in the conversation as attachments, under the turn's run, and the step record names the stored file. Uploads run in the background, so the agent does not wait for them; the turn waits up to 30 seconds for the last ones before it is saved. One turn uploads at most 64 screenshots and 64 MiB. If an upload fails or is over the limit, the step record says so and the turn goes on.

Turning on the upload, as a project admin (permission `models.project_settings.edit`):

```bash
curl -X POST "$DEPLOYMENT_URL/api/v2/configurations/configurations/$PROJECT_ID" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"elitea_title":"computer_use","label":"Computer use","type":"computer_use",
       "section":"project_settings","data":{"upload_screenshots":true}}'
```

The setting is off when the project has none. A turn reads it when it starts, so a change applies from the next turn.

## Turn it off

Set `"computer_use": false` in `settings.json`, or remove the key. The next call of a running turn is refused (`computer_use_off`), and the next turn has no `computer` tools. The same holds when your organization turns the policy off. To forget an **Always for this app** answer, remove it in the app's remembered choices.
