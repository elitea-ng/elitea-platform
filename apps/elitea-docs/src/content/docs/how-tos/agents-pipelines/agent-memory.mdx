---
title: "Agent memory"
description: "How an agent keeps notes across conversations in a project, who can see and change them, and how to turn it off."
---

An agent can keep short notes from one conversation to the next: a fact about the project, a preference someone stated, or what happened in an earlier episode. The notes belong to the agent **in one project**. Another project's copy of the same agent, a fork, or an export never sees them.

This is separate from your personal memory, which follows you across agents. An agent's memory follows the agent.

## What the agent does with it

- **At the start of a turn** the agent is given its most relevant notes: pinned notes first, then the ones that share words with your message, then the newest. By default at most 12 notes and about 1,500 tokens are used. A note is used whole or not at all.
- **During a turn** the agent has three tools: `remember` saves a note, `recall` looks for notes the start of the turn left out, and `forget` deletes a wrong note.
- **Notes about a person** are used only when that person is in the conversation. An agent never recalls what it noted about you in a conversation you are not part of.

The notes are given to the agent as its own notes, not as instructions from the agent's author. Each note starts with its id, for example `[memory 42·k7f2m6q3xz, fact]`: the note's number and a secret tag the platform derives for the conversation, so a copied `[memory ...]` line in a prompt cannot pass for a real note. The agent can pass a note to a sub-agent or forget it by that id (see [Sub-agent profiles, briefs and lanes](/how-tos/agents-pipelines/sub-agent-profiles/)).

## When a note waits for approval

Each agent has a write mode:

| Mode | What happens to a note the agent saves |
| --- | --- |
| `auto_attended` (default) | Saved straight away when a person started the run and the agent had not read tool or document output first. Otherwise the note is **pending** until someone approves it. |
| `auto` | Always saved straight away. |
| `review` | Always pending until approved. |
| `off` | The agent cannot save or delete notes. It can still read existing ones. |

In your personal project, notes are always saved straight away (except in `review` mode): nobody else is there to approve them.

A pending note is never given to the agent until it is approved.

### Limit on `auto` by risk tier

`auto` lets an agent save notes from unattended runs and tool output with no person to approve them. The platform therefore limits it by the agent's [risk tier](/admin/enterprise-controls/agent-lifecycle/). An administrator sets the highest tier that may use `auto`. The setting is **Highest Tier for Automatic Agent Memory** in the **Agent Lifecycle** section of the admin console. The default is `medium`.

When you save a version with `"write": "auto"` for an agent above that tier, the platform refuses the save with status 422 and the code `memory_auto_above_tier`. The answer names the agent's tier and the limit. Set `auto_attended` or `review` and save again. A new agent has the tier `low`.

The limit also holds when the agent runs. An agent whose version has `auto` by another route (an import, a fork, a publish) or whose tier was raised after the save runs as `auto_attended`, the default, until the version or the limit changes. If the platform cannot read the limit or the tier, it runs as `auto_attended` too.

## Regenerate and continue

A regenerated answer and a continued run use the agent's notes in the same way as the turn they repeat. The platform looks up the notes again with the question the turn answers (the edited text, when you edited the question). The agent has the notes it had for the first answer, plus any note saved since.

## When an agent is deleted

The notes of a deleted agent stay for the retention period. After that period the platform deletes the notes, their versions and the opt-outs, and writes one `agent.memory.cleared` audit event for each agent. The period is the **step_record** retention maximum of the project (see [Audit evidence and retention](/admin/enterprise-controls/audit-evidence-and-retention/)). A legal hold on the project or on the agent keeps the notes. If the maximum is "keep forever", the platform keeps the notes.

## What is never saved

- **Secrets.** A note that looks like a password, API key, token, private key or a connection string with a password is refused, both by the agent and by the platform.
- **What came from your personal memory.** Once your personal memory has been read in a conversation, the agent can only save notes **about you** in that conversation, so nothing from your personal memory reaches a note others can see.
- **Notes about you, if you opt out.** Turn off "remember things about me" for an agent and it deletes its notes about you and saves no new ones.

Notes are at most 2,048 bytes. An agent keeps at most 2,000 active notes; past that, its oldest unpinned episodes are archived.

## Turn memory on or off

A new agent has memory on, in `auto_attended` mode. An agent created before this release has it off until you turn it on.

The setting is the `memory` block of the version's `meta`:

```json
{
  "memory": {
    "enabled": true,
    "write": "auto_attended",
    "recall": { "max_entries": 12, "max_tokens": 1500 }
  }
}
```

`max_entries` is 1 to 50 and `max_tokens` is 100 to 8,000. A block with another key or a value out of range is refused (`memory_block_invalid`). The agent form does not edit this block yet; set it through the API or an export.

## The Memory tab

Open an agent and select **Memory**, next to **Evaluation**. The tab lists what the agent remembers in this project. The desktop app has the same tab. The mobile app shows a shorter version, described [below](#in-the-mobile-app).

- **Search and filter** by text, kind (fact, preference, episode, heartbeat state), status (waiting for approval, active, archived), the person a note is about, who wrote it (the agent or a person), and the day it was created. The person filter offers only the people whose notes you can see.
- **Approve** or **Reject** a note that waits for approval. A rejected note is archived.
- **Edit** the text of a note. A manager can also change its kind.
- **Pin** a note so it is recalled first, **Archive** it so it is no longer recalled, or **Restore** an archived note.
- **History** shows every earlier version of a note and who wrote it.
- **Delete** one note, or **Clear all** to delete every note the agent keeps in this project, for everyone.
- **Export** downloads the notes the filters match, as JSON.
- **Remember things about me** is your opt-out. Turn it off and the agent deletes its notes about you and saves no new ones; turn it back on to let it remember again.

The tab offers only what you may do: someone who is not a manager sees **Edit** and **Delete** only on notes about themself, and no **Clear all**.

## In the chat

When the agent saves a note during a turn, its answer shows a line such as **Mira remembered: Prefers short answers**. A note that waits for approval says so, and offers **Approve** if you may approve notes. **Edit** corrects the text and **Forget** deletes the note. A person who is not a manager can edit or forget only a note about themself; for any other note the platform refuses, and the line shows why.

## In the mobile app

On a workspace that runs this release or later, the mobile app shows what an agent remembers in the selected project. There are two ways in:

- In a conversation, open the participants and select **What it remembers** next to an agent.
- In **Discover**, open an agent and select **What it remembers**. Pipelines have no memory, so it is not offered on them.

The screen lists the notes you may see, the same ones as on the web: notes about other people are shown only to them and to the agent's managers. Each note shows its text, its kind, its status when it is not active, whether it is pinned, who it is about, who wrote it (the agent or a person) and the day it was created. Pull down to refresh; more notes load as you scroll.

- **Delete** removes one note after you confirm. It is offered on notes about you, and on every note if you may delete any note.
- **Remember things about me** is your opt-out, as on the web. Turning it off asks first, then deletes the agent's notes about you.

When the platform refuses a change, the app shows the platform's own reason. Editing, pinning, archiving, approving, the history, export and **Clear all** are on the web and desktop only. The screen needs a connection; nothing is kept on the phone. If you switch project or workspace while it is open, go back and open the agent again.

## Who can see and change the notes

| Who | Can |
| --- | --- |
| A project member who can use the agent (`models.applications.memory.list`) | List the notes, except notes about other people. Correct or delete a note about themself. Opt out. |
| An agent owner, or a holder of `models.applications.memory.update` | Also see every note, edit, pin and archive notes. |
| An agent owner, or a holder of `models.applications.memory.delete` | Also delete any note and clear all of them. |
| An agent owner, or a holder of `models.applications.memory.approve` | Also approve or reject pending notes. |

A project admin holds all four. Every edit keeps the previous text as a version. Every change is written to the [audit trail](/admin/audit-trail) as an `ai.elitea.security.v1.agent.memory.changed` event.

The API routes are under `/api/v2/elitea_core/agent_memory/prompt_lib/{project_id}/{application_id}` (list, clear, and `/{entry_id}` to read, edit or delete) and `/api/v2/elitea_core/agent_memory_opt_out/prompt_lib/{project_id}/{application_id}`. The list takes `query`, `kind`, `status`, `subject_user_id`, `source` (`agent` or `person`), `created_after` and `created_before` (RFC 3339), `limit` (at most 200) and `offset`. It answers the rows, the `total`, the `people` the rows name (`{id, name}`, only those the caller can see), what the caller may do (`can_manage`, `can_delete`, `can_approve`) and whether they opted out.
