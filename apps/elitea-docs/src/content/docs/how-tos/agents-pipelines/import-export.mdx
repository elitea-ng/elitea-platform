title: "Import and export entities"

Export lets you back up or move an agent, pipeline, toolkit, skill or conversation as a file; import brings an exported agent or pipeline back into a project.

## Export an agent or pipeline

Open the agent or pipeline, then use **Export** in the toolbar's three-dot menu. The download is an `.agent.md` file of the version you have open, in the [`elitea.agent/v1` format](/reference/agent-file-format): its model settings, toolkits, skills, memory settings, heartbeat schedule, tool envelope, run caps, persona, avatar and evaluation datasets are in the YAML front matter. An agent with uploaded avatar files downloads as an `.agent.zip`: the agent file and its avatar files. An agent's file does not carry its nested agents: export each of them as well, and attach them again after import. An agent's [avatar pack](/menus/agents#avatar) comes with its files, and import stores them in the destination project. Authentication credentials are never included — you reconfigure them after import.

## Import an agent or pipeline

<Steps>
<Step title="Open the import dialog">
On the **Agents** or **Pipelines** list, click **Import** and choose a `.json` export file, an `.agent.md` file (YAML front matter, then the instructions), an `.agent.zip`, or a `.zip` of `.md` agent files. To start from a ready-made file, see [Start from a blueprint](/how-tos/agents-pipelines/blueprints).
</Step>
<Step title="Review the summary">
Elitea reads the file and shows, before anything is created, the agent's name, description, avatar and model, or for several agents a list of them, and how many agents, toolkits and skills (and evaluation datasets and memory seeds, when there are any) the file carries. **Before you import** lists what to know: the toolkits that arrive without credentials, the heartbeat schedules to turn on later, and the agents whose file names no model. When **Import** cannot run, the text next to it says why; while an agent's avatar files upload, it says how many.
</Step>
<Step title="Confirm">
Confirm the import. The entity is created in your current project using the file's exported configuration. Each agent gets a model of this installation: the model the file names, if this installation has it in the file's project or in this project or as a shared model; else this project's default model. The dialog then says which model each agent runs on and its context window, and warns about each agent that got the project's default instead of the model in its file. Embedding settings fall back to the project's own configured defaults where the export didn't carry a credential.
</Step>
<Step title="Reconfigure credentials">
Any toolkit that needs a credential (API key, token) must be reconfigured manually — exports never carry secrets.
</Step>
</Steps>

<Screenshot id="entity-import-dialog" alt="Import dialog with an entity summary" />

Importing requires import permission in the destination project; the **Import** button is disabled without it. A file that isn't valid JSON, or has no exported agents in it, is rejected with an explanation rather than silently failing.

Import checks every agent with the rules of a save in the editor before it creates anything. The first problem stops the import, and the dialog names the field, for example `applications[0].versions[0].meta.run_caps.max_tool_calls`. The API answers HTTP 422 with `code: import_invalid` and the `field`. A file with a format version that this release cannot read, for example `elitea.agent/v2`, is refused. See [What import checks](/reference/agent-file-format#what-import-checks).

After an import, the summary lists what is left to do: the toolkits to connect, the memory notes that wait for your review on the **Memory** tab, and the agents whose heartbeat schedule you can turn on in the **Heartbeat** tab after you publish them. Import never turns a heartbeat on.

The toolkits a file carries are created in the project and linked to the agents that use them. Credentials are still yours to add.

## Export and import a team

A [team](/menus/agents) travels as a `.zip`: a `team.yaml` plus one `.agent.md` file per member.

- **Export.** On the **Teams** switch of the Agents page, open the team card's **⋯** menu and select **Export**. Each member is exported at the version the team uses.
- **Import.** On the **Teams** page select **Import team**, or on the **Agents** list (not the Pipelines list) select **Import**, and choose the zip. The summary shows the team's name and description above its agents, each with its avatar (the zip's own avatar files included) and its model, and the lead marked **Lead**. Confirm with **Import team**. Confirm, and Elitea creates every agent, its toolkits and skills, and the team, in one step.

A team import is all or nothing. If anything cannot be created, nothing is kept and the dialog says why:

- an agent of the file has the name of an agent already in the project (names are compared without case), or two files share a name;
- the team's name is taken in the project;
- an agent uses a toolkit the file does not carry, or a sub-agent that is not one of the team's members (a member's `.agent.md` does not carry its nested agents; add them to the team as members of their own);
- `team.yaml` lists a file the zip does not hold, or names a lead that is not a member.

Importing a team also needs the right to create teams in the project.

`team.yaml` lists the members by their paths inside the zip, relative to `team.yaml`:

```yaml
schema: elitea.team/v1                         # the format version; export always writes it
kind: team
name: Dev team
description: Builds and reviews the platform   # optional
members:                                       # 1 to 16, in roster order
  - agents/coordinator.agent.md
  - agents/implementer.agent.md
lead: agents/coordinator.agent.md          # optional: makes floor_policy lead
floor_policy: lead                             # optional: addressed (default without a lead) or lead
```

Only the member files are read, so a README beside them is fine. A zip without `team.yaml` imports its `.md` files as separate agents, as before.

## Export and import a skill

Skills export as a Markdown file (`Export` on a skill's page) and import the same way, from the **Skills** list's **Import** button. See [Create and share a skill](/menus/skills) for the full skill lifecycle.

## Export a toolkit

A toolkit's three-dot menu offers **Export**, producing a file with its type, name, settings and enabled tools — again with credentials excluded.

## Export a conversation

A conversation can be exported from its options menu, producing a copy of the conversation for backup or sharing outside the app.
