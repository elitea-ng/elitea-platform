title: "Agent workforce: scorecards, the dismissal ladder and appeals"
description: "Read an agent's daily scorecard, propose and decide watch, demote, suspend, retire or delete, let a reviewer agent propose them, appeal a decision, reinstate a retired agent, and turn on automatic hiring and dismissal."
---

Every agent of a project gets a daily **scorecard**. When an agent does badly, a person (or a reviewer agent) can propose a step on the **dismissal ladder**, and a person who manages agents decides it. The agent's owner can comment and appeal, and a retired agent can be reinstated for 30 days.

Open an agent and select the **Workforce** tab.

## The scorecard

Once a day the platform computes, for each agent, over the last 30 days:

- runs, failed runs and the failure rate, and runs stopped by a budget cap;
- circuit-breaker trips (last 7 days), approval rejections and guardrail hits;
- spend, next to the median spend of the project's agents;
- thumbs up and down on its answers;
- when it was last used, and its certification state.

The tab shows the latest scorecard and the failure-rate trend. Scorecards are kept for 400 days. The daily job pauses during a maintenance window.

## The ladder

| Stage | What it does |
|-------|--------------|
| **Watch** | Flags the agent as under review. Nothing else changes. |
| **Demote** | Takes away exactly what the proposal names: toolkits, the heartbeat, the capabilities `can_propose_agents` and `can_review_agents`, or its lead role in conversations; or sets its memory writes to need review. The heartbeat and the lead role go at once; the rest is written to the agent's draft and reaches its published version the next time you publish it. |
| **Suspend** | Suspends the agent with the agent kill switch, so its runs are refused. Any admin can lift it. |
| **Retire** | Unpublishes the agent and removes it from conversations and saved teams, drops it as a lead, turns its schedules and its heartbeat off and revokes its triggers. Other agents keep it as a sub-agent; their runs fail with `nested_agent_retired` until someone fixes them. Its history stays. |
| **Delete** | Only after a retirement and its 30-day window, and never under legal hold: removes the agent's memory, schedules, triggers and versions. |

Before you approve a suspension, retirement or deletion, the dialog shows what it touches: conversations, saved teams, agents that nest it, schedules, triggers and published versions. Retiring an agent other agents nest needs a confirmation.

A critical-tier agent and an agent under legal hold cannot be proposed for any stage.

## Propose a stage

Select **Propose a stage**, pick the stage and give the rationale. A demotion lists exactly what it takes away. The latest scorecard is saved with the proposal as evidence. Only one proposal per agent can be open.

You can propose if you manage agents in the project (permission `agents.workforce.manage`) or own the agent.

## Decide a proposal

A person with `agents.workforce.manage` (or the agent's owner) can **Approve** or **Reject**. A manager can first **Ask the owner**: the owner is notified and can **Comment** before anyone decides.

The `agents.workforce.manage` permission is granted to the project **admin** role on upgrade. Grant it to other roles under **Settings → Roles**.

## Reviewer (HR) agents

An agent whose version sets the capability `can_review_agents` is a reviewer agent. It gets a `propose_dismissal` tool and can propose watch, demote, suspend or retire for another agent of the project, with its evidence. It never decides. It cannot propose a stage for itself, for the agent that hired it, for an agent of a higher risk tier or for another reviewer agent. A refused attempt is audited.

```json
{
  "capabilities": { "can_review_agents": true }
}
```

## Appeal

The owner of an agent can **Appeal** an approved demotion, suspension or retirement once, within 30 days. Managers are notified. A manager who did not make the decision, and who does not own the agent, **grants** the appeal (the stage is reversed) or **upholds** it.

## Reinstate a retired agent

For 30 days after retirement, a manager can select **Reinstate**. The agent's published versions and release head, its conversation memberships, its lead roles, its saved team seats, its schedules, its triggers and its heartbeat come back, and its suspension is lifted. After the window it can only be deleted.

## Automatic hiring and dismissal

A project can let the platform act on its own. Both policies are **off** until a person with `agents.workforce.manage` turns them on under **Settings → Agent workforce**. That page also lists every automatic action, with **Undo**, **Keep** and **Object** where they still apply. Anyone who can read the project's agents can see the page; only a manager changes it.

The policy runs once an hour and pauses during a maintenance window.

### Automatic hiring

With **Hire proposed agents automatically** on, an open [agent proposal](/how-tos/agents-pipelines/agent-proposals) becomes an agent only when all of these hold:

- Every proposed tool is read-only, so the agent's risk tier is **low**. A tool that writes, sends, runs code or declares no category is not read-only.
- The spec ran successfully at least **Successful runs needed** times (default 3) as an ephemeral agent, and never failed.
- Fewer than **Agents on probation at once** (default 5) automatically hired agents are waiting for review.
- Nobody undid an automatic hire of the same spec in the last 30 days.

The new agent is **unpublished** (a draft version only) and has **no tools bound**. Its owner is the person the proposal was for. It is on **probation** until a manager reviews it. For the first 14 days a manager can **Undo** the hire, which retires the agent (it can still be reinstated for 30 days). At any time a manager can **Keep** it, which ends the probation. An agent on probation counts against **Agents on probation at once**, and the `probation_failed` rule applies to it.

### Automatic dismissal

With **Dismiss agents automatically by rule** on, the policy reads each agent's latest scorecard (no older than two days) against the project's rules. A rule is a list of conditions that must all hold and one stage: **watch**, **suspend** or **retire**. When several rules match, the strongest stage wins. The default rules are:

| Rule | Conditions | Stage |
|---|---|---|
| `breaker_trips` | 3 or more breaker trips in 7 days | Suspend |
| `failure_rate` | failure rate above 0.5 and at least 20 runs in 30 days | Watch |
| `unused` | unused for 90 days or more | Retire |
| `probation_failed` | hired automatically and failed its probation (a breaker trip, 3 guardrail hits, or more than half of at least 3 runs failed) | Retire |

Edit the thresholds on the settings page, or set the rules through the API (`PUT /api/v2/elitea_core/agent_workforce/prompt_lib/{project_id}/policy`). A condition reads one of `runs_30d`, `failed_30d`, `cap_reached_30d`, `failure_rate_30d`, `breaker_trips_7d`, `approval_rejections_30d`, `guardrail_hits_30d`, `spend_ratio`, `thumbs_down_30d`, `unused_days`, `auto_hired` or `probation_failed`, with `>=`, `>`, `<=`, `<` or `=`.

```json
{
  "id": "too_expensive",
  "conditions": [{ "metric": "spend_ratio", "op": ">=", "value": 5 }],
  "stage": "watch"
}
```

- **Watch** and **suspend** apply at once. They go through the same ladder as a person's decision, so an appeal and reinstatement work the same way.
- **Retire** is first a notice. The agent's owners and the managers are notified, and the agent is retired only after the **grace period** (default 7 days). Until then the owner or a manager can **Object**: the notice is withdrawn and the rule leaves the agent alone for 30 days. A manager can also reject the notice in the agent's **Workforce** tab.
- A retire that would break agents that nest this one is **held** for a person instead of applied.

The policy never demotes or deletes, never goes past retire, and never acts on a **critical-tier** agent or an agent under **legal hold**. It skips an agent that already has an open proposal. Turning automatic dismissal off cancels its pending notices.

### Agents whose owner left

When neither owner of an active agent is a member of the project any more, the agent is flagged and the managers are notified so they can assign a new owner. If nobody does within 30 days, the agent is moved to **watch**. It is never retired for this reason. The flag clears as soon as an owner is a member again.

## Audit

Each step writes one `ai.elitea.security.v1.agent.workforce.changed` event, with action `agent.workforce.proposed`, `.approved`, `.rejected`, `.asked_owner`, `.owner_commented`, `.appealed`, `.appeal_granted`, `.appeal_upheld`, `.reinstated` or `.guard_refused`. The automatic policy adds `agent.workforce.policy_changed`, `.auto_hired`, `.auto_hire_undone`, `.auto_hire_kept`, `.policy_applied`, `.policy_objected`, `.policy_held` and `.orphan_flagged`, and an automatic hire also writes `agent.proposal.auto_hired`. The policy's own steps name the rule as the actor (`policy:<rule>`). See [Audit trail](/admin/audit-trail/).
