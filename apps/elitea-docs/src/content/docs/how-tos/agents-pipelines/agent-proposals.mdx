title: "Agent proposals and Copy to project"
description: "Let an agent propose saving a sub-agent that worked well as a new agent, review the proposal, and copy a personal agent into a team project."
---

An agent that starts sub-agents with `spawn_agent` can **propose** that one of them is kept as an agent of its own. The proposal is only a suggestion: nothing is saved as an agent until a person reviews it and selects **Create agent**.

## Let an agent propose agents

Two things must both be true:

- The agent version has the capability `can_propose_agents`. Set it in the version's `meta`:

  ```json
  { "capabilities": { "can_propose_agents": true } }
  ```

  Any other value, or no `capabilities` block, means the agent cannot propose. Save refuses a `capabilities` block that is not an object of `true`/`false` values.

- The person the agent runs for may create agents in the project (the `models.applications.applications.create` permission, which project editors and admins have).

The agent then gets a `propose_agent` tool, next to `spawn_agent`. Only an agent you saved can propose: a sub-agent cannot, and neither can an ad hoc agent.

## What the agent proposes

The agent names the sub-agent by the id `spawn_agent` answered, and says why it should be kept. It may add instructions for the new agent and up to 20 memory entries it could start with:

```json
{
  "ephemeral_agent_id": "a_1f2e3d4c",
  "rationale": "It reviewed three migrations quickly and found the risky one.",
  "instructions": "Review database migrations and list the risks.",
  "memory_seeds": [{ "kind": "fact", "content": "The project uses PostgreSQL 18." }]
}
```

The sub-agent's profile (display name, soul, tools and avatar) is taken from the run itself, not from the call, so the proposal is exactly the sub-agent that ran. The project is always the run's project.

The platform keeps each proposal with its evidence: the run, the conversation, and how the sub-agent's run ended and what it spent.

### Limits

- An agent has **at most 3 open proposals**. A fourth is refused until one is created or dismissed.
- Proposing the same sub-agent profile again answers the existing proposal.
- A profile that someone **dismissed** is not proposed again for **30 days**.

## Review a proposal

A proposal shows up in two places:

- **In the chat**, under the answer: "Mira proposes saving a sub-agent as a new agent: Risk reviewer", with **Review**.
- **On the Agents page**, as **Proposals (n)** in the toolbar, for a person who may create agents. Select it to see the open proposals.

**Review** opens the agent form filled in from the proposal: name, description, instructions, display name and soul. It also shows:

- **Proposed tools**, each with its category (Read, Write, Sends externally, Spends money, Destructive). A tool the platform has no category for, or a wildcard such as `github/*`, counts as Write. Tools are **not** added by Create: add them in the agent editor, where their checks apply.
- **Memory to start with**: tick the entries to keep. Only the ticked ones are saved into the new agent's memory.
- The new agent **starts at the Low risk tier**, whatever the proposing agent's tier is.

Then:

- **Create agent** creates the agent and opens it. The proposal is marked created.
- **Dismiss** closes the proposal. The same profile is not proposed again for 30 days. A person who may create agents, or the owner of the proposing agent, may dismiss.
- **Save locally as AGENTS.md / SOUL.md** downloads the agent's description, instructions, tools and memory as `AGENTS.md`, and its soul as `SOUL.md`. It saves nothing on the platform. The desktop app reads both files from a Local work folder.

## Copy a personal agent to a project

An agent in your personal project has **Copy to project** in the agent editor. Pick a team project and, optionally, memory entries to copy.

- The copy is **an agent of its own**. Changing or deleting one never changes the other.
- Only the memory you pick is copied, and only active notes about nobody. Notes **about a person** stay in your personal project.
- You need to be able to create agents in the target project.

Copy to project is the same as [forking](/how-tos/agents-pipelines/forking), plus the memory.

## Audit

Each proposal, creation, dismissal and copy writes one `ai.elitea.security.v1.agent.proposal.changed` event (action `agent.proposal.proposed`, `.created`, `.dismissed`, `.seeded` when kept memory was saved into the new agent, or `agent.copied_to_project`). The event holds no draft or memory text. See [Audit trail](/admin/audit-trail).
