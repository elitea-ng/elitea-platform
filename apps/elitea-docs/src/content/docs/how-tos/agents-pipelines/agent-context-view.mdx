---
title: "What an agent sees of a conversation"
description: "How each agent in a multi-agent conversation gets its own view of the history, sized by its own model, and how to narrow it."
---

When several agents take part in one conversation, each one gets **its own view** of it on every turn. Main builds that view for the agent that answers, just before the turn starts.

## What is in a view

- **Visible messages only.** People's messages and agents' answers: text, attachments and canvases. Another agent's tool calls, tool results and thinking are never in it.
- **Labelled.** A message from another agent or another person comes with its author's name, so the agent never takes a peer's words for its own.
- **Side talk only for its party.** Messages two agents exchange on the side are in the view of those two agents only. A third agent never sees them.
- **Sized by the agent's own model.** The budget is the context window of the agent's model, frozen into its version. When the conversation is longer than that, the agent's own compaction summarises the older part. Two agents on models with different windows get different summaries.

## Narrowing the view

In the agent editor, open **Advanced** and set **Conversation history**. It has two choices:

- **What it reads:**
  - *Everything it may see*
  - *Since it joined*
  - *Only messages addressed to it*
  - *None (the current message only)*
- **Side talk:**
  - *Side talk it is a party to*
  - *No side talk*

Leaving both at their first option stores no block. If the server refuses the block, its refusal shows under the field after **Save**.

The editor writes a `context` block to the version's meta:

```yaml
context:
  history: full              # full | since_joined | addressed_only | none
  include_side_talk: party   # party | none
```

| `history` | The agent sees |
| --- | --- |
| `full` (default) | Every visible message it may see. |
| `since_joined` | What was said after it joined the conversation, and its own answers. |
| `addressed_only` | Messages addressed to it, its own answers, and the messages those replied to. |
| `none` | No other messages: only the current message and the agent's own exchanges with the person asking since the mode was set, which its own session keeps. |

`include_side_talk: none` leaves out even the side talk the agent took part in.

A version without the block is `full` and `party`. A save with an invalid block is refused with `422 context_block_invalid`.

## "Share history from: now"

When you add an agent from the **+** menu to a conversation that already has messages, the chat asks **Share history from**:

- **The start.** The agent uses its version's own mode.
- **Now.** The agent sees only what is said from that moment on, plus its own answers.

"Now" sets the participant's `entity_settings.context_history` to `since_joined`. The join time is the moment you add it. If you remove the agent and add it again with "Now", the join time moves to the new add. Adding it again with "The start" keeps the old join time.

This only narrows. An agent whose version already sees less keeps its own mode. Any value other than `since_joined` or `full` is refused with 422.

## "What the agent saw"

To see what an agent was given for one answer, open the answer's **⋯** menu and choose **What the agent saw**. It is read-only and shows:

- **The view's settings:**
  - the agent;
  - its history mode, and the mode set for it in this conversation, if any;
  - side talk;
  - the window in tokens;
  - the view's digest.
- **Context:** the last context measurement the runtime reported for the answer (`measured`, `compacting` or `compacted`, with the estimated, usable and trigger token counts).
- **Messages it saw.** Each visible message the agent was given, by author, time and id.
- **Messages it did not see.** Each visible message left out, with the reason:
  - side talk it is not a party to;
  - side talk is off for this agent;
  - history is off for this agent;
  - sent before it joined;
  - not addressed to it.

The inspector never shows a message's text. It never shows another agent's tool calls or thinking, and it never shows the view of another agent or person. Only an answer's own agent has a view, and the server answers 404 for anything else. You need the same access as for the conversation: the `models.chat.messages.details` permission and access to the conversation. Answers from before this release, and replies that are not an agent's, show "No view was recorded for this answer."

The endpoint is `GET /api/v2/elitea_core/message_context_view/prompt_lib/{project_id}/{message_id}`. Its response is not cached.

The inspector shows what Main sent on that turn. When the agent's mode has changed, the agent's own session is started again from that view, so the model holds no message the view left out. See below.

An answer that paused for an approval or a question and then went on shows the view of the run that finished it: the continued run records its view again over the one recorded when the answer started.

## When the mode changes

The agent's own session is bound to the view it was started under: its mode, side talk, and (for `since_joined`) the join time. On the agent's first turn after any of these changes (a new version with another `context.history` or side-talk setting, "share history from: now" set on its participant, or the agent removed and added again), the worker checks the session against the current view:

- **It holds only what the view holds**, in the view's order, with nothing the view leaves out, no gap before its recent turns, and exactly the agent's own earlier exchanges the view includes: the session is kept and only rebound to the new view. Its tool results, compaction summary and prompt cache stay. This is the common case when a view only widens past what the session already had, or when a setting changed that removes nothing it holds.
- **Otherwise** the worker starts the session again from the current view. The model then sees exactly that view and the agent's own turns from then on, in conversation order:

- **Narrowed:** messages the new mode leaves out are gone from the session, not only from what is sent.
- **Widened:** the older messages the new mode lets in appear where they were said, not after the recent turns.
- **Nothing changed:** the session is kept and the model gets the same bytes as before, so the provider's prompt cache still matches.

Starting again costs one turn without the prompt cache, and drops the session's own compaction summary; the agent's compaction summarises the new view again if it is longer than the model's window. Changing to `none` also drops the agent's earlier exchanges with the person asking, as `none` sends no earlier messages.

A session started before this check is checked the same way on its first turn after the upgrade: kept if it holds only what the view holds, started again once if it holds side talk it is no party to.

When the agent can start sub-agents, a session holding messages without their short `[message m-…]` ids (from before the ids) is started again too, so every message a brief can quote is one the agent saw under its id. A regenerated answer asks its question again under that question's id, so regenerating no longer starts the next turn's session again.

## Pipelines

A pipeline that takes part in a conversation gets its view the same way. Its graph state holds the view as `chat_history`, set once when the run starts. See [Pipeline structure](/how-tos/pipelines/structure/#chat_history-the-conversation-so-far).

## How the worker checks it

Main sends the view with a digest over its mode, its window, and the exact history and references. The worker recomputes the digest and refuses a turn whose history does not match it, so a view is never widened on the way.
