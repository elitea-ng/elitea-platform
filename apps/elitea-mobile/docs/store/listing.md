### Age rating (App Store Connect questionnaire, 2025 version)

Apple's questionnaire now has 4+, 9+, 13+, 16+ and 18+ results and new
questions on in-app controls, capabilities, medical or wellness topics and
violence. Suggested answers, then let App Store Connect compute the rating:

| Question | Answer | Why |
|---|---|---|
| Cartoon or fantasy violence, realistic violence, prolonged graphic violence | None | the app shows no such content of its own |
| Profanity or crude humor; mature or suggestive themes; horror or fear themes | **Infrequent** | AI answers are generated by the workspace's models and are not filtered by the app |
| Sexual content or nudity; graphic sexual content | None | |
| Alcohol, tobacco, drugs; simulated gambling; real gambling; contests | None | |
| Medical or treatment information; health or wellness topics | **Infrequent** | a user can ask an agent anything |
| Messaging and chat | **Yes** | conversations with agents; workspace members may share conversations |
| User-generated content | **Yes** | messages and attachments |
| Social media (feed or discovery of user content) | No | Discover lists agents, not user posts |
| Unrestricted web access | No | the app opens links in the system browser sheet; it has no browser of its own |
| Advertising | No | |
| Parental controls; age assurance | No | |

Expected result: **13+** (16+ if Apple scores generative-AI answers higher).
The owner may choose a higher rating than computed (for example 17+/18+ "for
workplace use"); a higher rating never causes a rejection, a lower one can.

## Review notes (both stores)

Reviewers must reach a signed-in workspace, and the app has no account sign-up
or demo mode. The owner must create, **before the first external TestFlight
round and before each review**:

1. **A demo workspace** reachable from the internet (for example
   `https://demo.agent.zefir.ca`, or the existing demo server), with native
   clients enabled for `ca.zefir.agent`, a public agent or two in Discover, a
   project with a few sample conversations, and models that answer.
2. **A reviewer test account** on that workspace's identity provider: a
   username and password sign-in that needs **no** MFA app, SMS, hardware key or
   corporate VPN, valid for at least the review period. A dedicated
   local-password identity provider or a test user in the SSO tenant both work;
   do not reuse a real person's account.
3. Keep both alive: a review that cannot sign in is rejected under guideline
   2.1 (App Completeness).
