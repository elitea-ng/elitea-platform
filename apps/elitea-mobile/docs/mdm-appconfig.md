# Managed app configuration (MDM / EMM)

An MDM or EMM (Intune, Workspace ONE, Jamf, Kandji, Google's Test DPC, ...)
can configure the mobile app on managed devices. Both platforms take the
same keys and go through one parser (`src/security/managedConfig.ts`):

- **iOS (AppConfig):** the managed UserDefaults key
  `com.apple.configuration.managed`.
- **Android (managed configuration):** the app restrictions an EMM sets.
  The app declares them in `res/xml/app_restrictions.xml` (generated by
  `plugins/withManagedConfiguration.js`), so the EMM console lists them
  with their types. The inline module `native-modules/ManagedRestrictions.kt`
  reads them.

The app reads the configuration at launch and again whenever the MDM changes
or removes it while the app runs. Removing the configuration, or unenrolling
the device, drops the lock floor and the managed address at once, not at the
next launch.

| Key | iOS type | Android type | Effect |
|---|---|---|---|
| `server_url` | string | `string` | The organization's workspace. The connect screen shows it read only ("Managed by your organization") and offers no other server: no typed address, no connect link to another server, no "use this address instead". The usual address checks apply (https only, no credentials in the URL); a value that is not a workspace address is ignored. |
| `lock_server` | boolean | `bool` | With `server_url`: the device keeps **only** that workspace. Every workspace on another server is signed out and its data removed, exactly as at "Log out & wipe"; "Add workspace" is gone. Without a usable `server_url` it does nothing. Removing the key restores nothing. |
| `require_device_lock` | boolean | `bool` | `true` requires Face ID / Touch ID / fingerprint / passcode at launch, whatever the workspace policy says. `false` changes nothing. |
| `idle_lock_seconds` | integer, 1 to 86400 | `integer` | With a device lock, relock after this many seconds in the background when it is shorter than the workspace's (or the workspace sets 0, "never relock"). `0` changes nothing. |
| `allow_screenshots` | boolean | `bool` | `false` blocks screenshots and screen recording, and hides the app-switcher snapshot where the device allows it. `true` changes nothing. |

The lock keys are a **floor**: they only ever tighten the workspace's client
policy, never loosen it. Settings says when the device management made the
lock stricter. A key of the wrong type is ignored (a string `"true"` is not
a boolean). On iOS a plist boolean may arrive as `1` / `0`; both count. The
configuration belongs to the device, not to a workspace: logging out of a
workspace does not remove it.

## Feedback to the MDM

While the device has a managed configuration, the app reports its state back to
the MDM (src/security/managedFeedback.ts), so an administrator sees a
misconfigured or signed-out app in the console:

- **iOS:** the managed feedback dictionary `com.apple.feedback.managed` in the
  app's UserDefaults, read by the MDM's ManagedApplicationFeedback command
  (Intune and Workspace ONE show it per device and app). Each value is a code,
  or `code:data`.
- **Android:** keyed app states (androidx.enterprise `KeyedAppStatesReporter`,
  through native-modules/ManagedRestrictions.kt) sent to the device or profile
  owner and Play, readable in the EMM console or the Android Management API.

| Key | Info codes | Error codes | Data |
|---|---|---|---|
| `managed_config` | `applied` | `ignored_keys`: a key of ours with a value the app refused | the ignored key names, comma-separated |
| `connection` | `managed_server`, `other_server` (no managed address), `not_connected` | `managed_server_invalid` (`server_url` is not a workspace address), `other_server` (connected to another server than the managed one) | none |
| `sign_in` | `signed_in`, `signed_out` | `signed_out_device_revoked`, `signed_out_credential_rejected`, `signed_out_policy`, `signed_out_managed_server` | none |
| `policy` | `ok` | `update_required`: the workspace asks for a newer app | the minimum version |

**Never user content:** no server address (not even the managed one), account,
project, name, email, message or error text; only the fixed keys and codes
above, managed key names and a version number. The test
(src/security/managedFeedback.test.ts) holds every state to these lists.

Dormant without an MDM: with no managed configuration nothing is written, and
when the MDM removes the configuration the iOS dictionary is removed.

## Microsoft Intune

**iOS:** Apps › App configuration policies › Add › Managed devices, choose
the app, then "Use configuration designer" with the keys above, or "Enter
XML data":

```xml
<dict>
  <key>server_url</key><string>https://ai.example.com</string>
  <key>lock_server</key><true/>
  <key>require_device_lock</key><true/>
  <key>idle_lock_seconds</key><integer>60</integer>
  <key>allow_screenshots</key><false/>
</dict>
```

**Android Enterprise:** Apps › App configuration policies › Add › Managed
devices, platform Android Enterprise, choose the app, then "Configuration
settings format: Use configuration designer". Intune lists the keys from the
app's restrictions with their types; set `server_url` to
`https://ai.example.com`, `lock_server` and `require_device_lock` to `true`,
`idle_lock_seconds` to `60`, `allow_screenshots` to `false`. As JSON data:

```json
{
  "kind": "androidenterprise#managedConfiguration",
  "productId": "app:ai.elitea.app",
  "managedProperty": [
    { "key": "server_url", "valueString": "https://ai.example.com" },
    { "key": "lock_server", "valueBool": true },
    { "key": "require_device_lock", "valueBool": true },
    { "key": "idle_lock_seconds", "valueInteger": 60 },
    { "key": "allow_screenshots", "valueBool": false }
  ]
}
```

## Workspace ONE UEM

**iOS:** Apps & Books › the app › Assignment › "Send Application
Configuration", one row per key:

| Configuration Key | Value Type | Configuration Value |
|---|---|---|
| `server_url` | String | `https://ai.example.com` |
| `lock_server` | Boolean | `true` |
| `require_device_lock` | Boolean | `true` |
| `idle_lock_seconds` | Integer | `60` |
| `allow_screenshots` | Boolean | `false` |

**Android:** Apps & Books › the app › Assignment › "Application
Configuration". Workspace ONE reads the app's restrictions and shows one
field per key; fill them in as above.

## Testing without an MDM

- **iOS simulator:** `xcrun simctl spawn booted defaults write <bundle id>
  com.apple.configuration.managed -dict server_url https://ai.example.com
  lock_server -bool true` (an MDM test profile on a device, for the real
  path).
- **Android:** install Google's Test DPC, make it the profile or device
  owner, then "Manage application restrictions" › the app: the keys above
  appear with their types. Test DPC's "Keyed app states" screen shows the
  feedback the app reports.
- **iOS feedback:** `xcrun simctl spawn booted defaults read <bundle id>
  com.apple.feedback.managed` prints the dictionary the app wrote.

Other brands: replace `ai.elitea.app` with the brand's Android application
id (its brand manifest, `brand/<id>/brand.json`).
