# Agent Zefir

Agent Zefir is an independent native mobile client (iOS and Android) for
Elitea AI-agent platform servers, whether SaaS or
self-hosted. Connect to your organization's workspace, sign in through your
organization's usual SSO, and chat with your workspace's agents on the go.

Built with Expo (React Native) and TypeScript.

> **Non-affiliation notice.** Elitea is a trademark of its respective owner. Agent
> Zefir is an independent client and is not affiliated with or endorsed by it.
>
> This repository contains no code from the Elitea projects. The only coupling is
> a pinned copy of the server's published OpenAPI contract (`contract/`, to be
> added), from which this app generates its own client.

**Status:** early skeleton. The screens are placeholders and there is no networking yet.
See [docs/design.md](docs/design.md) for the planned product and
[docs/open-questions.md](docs/open-questions.md) for decisions still open.

## Identifiers

All identifiers are defined once in [`app.config.ts`](app.config.ts). Runtime code
reads them through [`src/config/identity.ts`](src/config/identity.ts); do not
hardcode them anywhere else.

| What | Value |
|------|-------|
| Display name | `Agent Zefir` (the same for every customer; there are no per-customer builds) |
| Expo slug | `agent-zefir` |
| iOS bundle identifier | `ca.zefir.agent` (permanent) |
| Android application id | `ca.zefir.agent` (permanent) |
| Connect-link scheme (primary) | `zefir`, as in `zefir://connect?server=https://ai.example.com` |
| Connect-link scheme (alias) | `agentzefir` |
| OAuth redirect (RFC 8252) | `ca.zefir.agent:/oauth/callback` |
| Website | https://agent.zefir.ca (privacy: `/privacy`, support: `/support`) |

## Running it

You need Node.js and npm. This is a standalone npm project with its own
`package-lock.json`. It is not part of any surrounding npm workspace.

```bash
npm install
npm start            # Expo dev server (press i / a for a simulator, or scan with a dev build)
npm run typecheck    # tsc --noEmit
npm run lint         # expo lint
npm test             # jest (jest-expo preset)
npx expo-doctor      # dependency and config health
```

Native `ios/` and `android/` directories are generated by `npx expo prebuild`
(Continuous Native Generation). They are git-ignored, and you configure native
behaviour in `app.config.ts` and config plugins, not by editing them. Planned
native modules such as SQLCipher, secure storage and biometrics require a
development build (`npx expo run:ios|android` or EAS Build), not Expo Go.

## Repository layout

```
app.config.ts              Expo config, the single source of the identifiers above
src/
  app/                     expo-router routes
    _layout.tsx            root: providers, and a redirect to /connect when no server is set
    connect.tsx            first run: "Connect to your workspace"
    (app)/                 signed-in area
      _layout.tsx
      index.tsx            conversations list (placeholder)
      settings.tsx         current server, "Log out & wipe" (placeholder)
  config/identity.ts       runtime access to the app identifiers
  constants/               fallback theme (overridden by the server's brand pack later)
  linking/parseConnectLink.ts   connect-link, QR-payload and typed-URL parser (+ tests)
  state/workspace.tsx      in-memory workspace selection (React context)
assets/                    placeholder icons and splash
docs/
  design.md                product and security design
  open-questions.md        unresolved decisions
contract/                  (planned) pinned OpenAPI v2.yaml of the server
```
