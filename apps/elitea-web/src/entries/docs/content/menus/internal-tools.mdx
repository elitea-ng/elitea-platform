---
title: "Internal tools"
description: "Built-in chat and agent capabilities — image creation, data analysis, attachments, planner, swarm mode, and smart tools selection."
---

Internal tools are capabilities you turn on from **Modules** in chat or an agent's Tools section, without configuring an external toolkit. They come from a fixed platform catalogue (`features/agents/lib/internalTools.ts`) and are turned on per conversation or saved as an agent's default.

<Note title="Which worker runs which module">
**Planner**, **Attachments**, **Data analysis** and **Smart tools selection** run on the platform's agent worker. **Image creation**, **Elitea MCP tools** and **Swarm mode** are not run by the platform's worker: they show disabled with a "Not available on the Rust worker" note (agent Tools section) so you can see the gap before turning one on, and a run that still hits one gets a visible in-conversation notice rather than the capability silently doing nothing (tracked in #866).
</Note>

## Turn a module on

<Tabs>
  <Tab title="In chat">
    Select **+** in the chat toolbar → **Modules**, then toggle the tool on. The setting lasts for the conversation.
  </Tab>
  <Tab title="On an agent">
    Open the agent, find **Modules** under **Tools** (select **Show all** if it is collapsed), toggle the tool, and **Save**. New conversations with that agent turn it on by default.
  </Tab>
</Tabs>

## Image creation

Generates images from a text prompt and shows them inline, using an image-generation model configured in **AI Providers**. Generated images are saved automatically to the project's `attachments` bucket, where you can also download or delete them later from [Artifacts](/menus/artifacts).

<Tip>
This toggle is a chat-conversation setting. To let an agent or pipeline generate or edit images as a step in its own logic — not just inline in chat — attach the [ImageGen toolkit](/integrations/toolkits/imagegen_toolkit) instead.
</Tip>

## Data analysis

Runs pandas-style analysis over a file you upload to the conversation — summaries, filtering, aggregation, and chart generation — driven entirely by natural-language requests. Upload the file first, then ask for the analysis; generated charts and exported files are saved back to the conversation.

<Tip>
For datasets larger than about 100 MB, or analysis needing custom code, use a Python-based toolkit or a pipeline Code node instead.
</Tip>

## Attachments

Lets the agent list, read and search the files attached to the conversation — including ones attached in earlier messages — with `list_attachments`, `read_attachment` and `search_attachment`. A file small enough to fit is already shown to the model with your message; the tools reach the rest of a long document and the files from earlier turns. Each file is read from storage the first time the agent asks for it. Turn it on from the agent's **Tools** section (it is not in the chat toolbar).

## Planner

Lets an agent write a plan for a multi-step task and tick it off as it works: a title and numbered steps that move from pending to in progress to completed (`update_plan`, `start_step`, `complete_step`, `get_plan_status`, `delete_plan`). The plan belongs to the conversation: it is kept between messages and survives long conversations being summarised, and deleting the conversation removes it. The agent is also given short planning guidance in its instructions while the module is on.

## Swarm mode

Turns a set of agents into peers that can hand off control to one another mid-conversation, all sharing the same conversation history. The agent the user addresses is simply the default entry point; any peer can transfer to any other with a `transfer_to_<agent_name>` tool, and each hand-off's task argument must be fully self-contained — the receiving agent gets no other context. Swarm-enabled agents cannot themselves be added as a child of another swarm agent.

## Smart tools selection

Reduces token usage when an agent has many toolkits configured by binding only two meta-tools (`get_tool_schema`, `invoke_tool`) instead of every individual tool definition, loading real tool schemas on demand, and adding a compact index of the available toolkits and tools to the agent's instructions. Turn it on once a conversation or agent uses five or more toolkits — the more toolkits, the larger the savings. With fewer than 20 tools the module switches itself off for that message, since the meta-tools would cost more than they save.

<Note>
A tool that needs your confirmation (a sensitive action) or a sign-in to the service stays directly available to the agent instead of going through `invoke_tool`, so approvals keep working exactly as without the module. The Planner, Attachments and this module apply to the agent you chat with; agents it calls as tools, and pipeline steps, do not get them.
</Note>

## Troubleshooting

<AccordionGroup>
  <Accordion title="A module toggle has no effect">Check the worker note under [Internal tools](/menus/internal-tools): Image creation, Elitea MCP tools and Swarm mode are not run by the platform's worker — the conversation shows a visible notice rather than running them.</Accordion>
  <Accordion title="Image creation is missing from the list">No image-generation model is configured for the project yet — add one in [AI Providers](/menus/settings/ai-providers).</Accordion>
  <Accordion title="Modules are missing from the chat toolbar entirely">No module is available for the project at all — ask your administrator to configure at least one provider or toolkit.</Accordion>
</AccordionGroup>
