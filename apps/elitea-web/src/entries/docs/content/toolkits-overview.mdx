A toolkit gives an agent a set of callable tools backed by an external
service — a code repository, a project tracker, a documentation source. An
agent with a toolkit attached can read from (and, where the toolkit allows
it, write to) that service as part of answering a message.

## Adding a toolkit to a project

1. Open the project's **Toolkits** settings.
2. Choose a toolkit and provide the credentials it asks for (an API token, a
   base URL, or both, depending on the service).
3. Attach the configured toolkit to an agent so its tools appear in that
   agent's tool list.

<Tip>
Credentials are stored once per project and can be reused by every toolkit
and agent in that project — you do not re-enter them per agent.
</Tip>

## What a toolkit exposes

| Category | Examples | Typical use |
| --- | --- | --- |
| Code repositories | source hosting, pull requests | reading and proposing code changes |
| Project management | issue trackers | reading and filing issues |
| Documentation | wikis, knowledge bases | answering from indexed docs |

<Warning>
A toolkit's tools run with the credentials configured for the project, not
the credentials of whoever is chatting — a member of the project can trigger
any action the toolkit's stored credential is allowed to perform.
</Warning>
