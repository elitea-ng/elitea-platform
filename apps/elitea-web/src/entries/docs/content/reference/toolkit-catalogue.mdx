---

Elitea serves 52 toolkit types from a single catalogue. Which ones you can actually create a tile for depends on the **worker** your deployment runs: a type the running worker cannot build is hidden rather than shown broken, and an administrator can additionally restrict specific types per project on the Toolkit types page. No feature flag gates an individual type — only worker capability and that admin restriction do.

<Warning title="Helm and compose default to different workers">
Kubernetes/Helm deployments default to the **Rust** worker (22 types materialize). The one-host compose stack defaults to the **Python** worker (43 of 52 types import successfully). Your administrator can override the default; ask which worker is running before assuming a type is available.
</Warning>

Create a toolkit from `/toolkits/create/<type>`; MCP-shaped types are created from `/mcps/create` instead.

## Index-capable types

These 20 types carry a `pgvector_configuration`/`embedding_model` pair and show the Indexes panel once PGVector and an embedding model are configured: Artifact, Memory, VectorStore, ADO boards, ADO plans, ADO repos, ADO wiki, Bitbucket, Confluence, Figma, GitHub, GitLab, Jira, QTest, Sharepoint, TestRail, XRAY cloud, Zephyr Enterprise, Zephyr Essential, Zephyr Scale. See [Indexing overview](/how-tos/indexing/indexing-overview).
