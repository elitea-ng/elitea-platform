---
title: "Schedules and tasks"
description: "Switch recurring platform routines on or off, change their schedules, and see what background work is currently running."
---

Two admin pages cover recurring and running work: **Schedules & Tasks** for the platform's recurring routines, and **Tasks** for a live view of background jobs.

## Manage schedules

Open **Schedules & Tasks**. It lists every recurring routine the platform runs: the scheduled jobs of the main service (index schedule scan, pipeline schedule scan, artifact retention, token expiry notices) and the workers of the scheduler service (price sync and the retention sweeps). Each row shows the schedule in force, whether the routine is on, when it last ran and its outcome, and when it runs next.

<Steps>
  <Step title="Switch a routine off or on">
    The switch stops a routine from running without deleting anything. A routine that is switched back on waits for its next scheduled time; it does not replay the runs it missed.
  </Step>
  <Step title="Change its schedule">
    Click the schedule and enter an interval such as `30m` or `6h`, or five cron fields. Each routine has a shortest allowed gap, and a faster schedule is refused with the reason. Leave the field empty to go back to the default that the deployment sets.
  </Step>
  <Step title="Check the result">
    Changes apply within about a minute, without restarting anything. Every change is recorded in the audit trail with who made it.
  </Step>
</Steps>

<Screenshot id="admin-schedules-table" alt="Schedules & Tasks page listing the platform's recurring routines" />

<Note>
What a routine does is fixed in code and cannot be edited here: only whether it runs, and when. The editing controls need the `configuration.scheduling.schedules.edit` permission; with only the view permission the page is read-only. If the scheduling registry cannot be read, the main service's scheduled jobs pause until it can, rather than running unchecked.
</Note>

## See what is running

Open the separate **Tasks** page for a live view of background work this platform actually tracks: index runs, agent turns, toolkit tool calls, scheduled occurrences, and evaluation runs.

<Steps>
  <Step title="Filter by kind">
    Narrow the list to one kind of task.
  </Step>
  <Step title="Cancel a task">
    The cancel control only appears on rows the server reports as cancellable — a task past that point does not offer it, rather than offering a control that would mostly answer with a conflict.
  </Step>
</Steps>

<Screenshot id="admin-tasks-table" alt="Tasks page listing running background work" />

<Note>
There is no start control and no log tail here. Starting a task and reading its output are not modeled by this page — a task's output is its own artifact rather than a live log stream.
</Note>
