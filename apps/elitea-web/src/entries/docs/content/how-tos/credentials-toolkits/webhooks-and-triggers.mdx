A pipeline has two unattended ways to start without a person watching a chat: an inbound webhook trigger and a cron schedule. Both live together in the pipeline editor's **Triggers & schedules** section, and both exist so you can wire a pipeline into an external process — a CI job, an issue-tracker automation, a recurring maintenance task — without anyone opening a conversation to kick it off.

## Pipeline triggers

<Steps>
1. Open a pipeline's configuration and expand **Triggers & schedules**.
2. Reveal the trigger's secret URL (hidden until you explicitly show it) or rotate it if you suspect it's been exposed.
3. Configure the external system (GitHub, GitLab, or any custom sender) to POST to that URL when the event you want fires.
4. Send the secret as an `Authorization: Bearer` header where the sender supports it — a token embedded in the URL itself is accepted as a fallback, but it's the less safe option since URLs get written to proxy and browser logs.
</Steps>

<Note>
The same section also configures the cron schedule, and an agent's info panel shows which trigger type (chat message, schedule, or webhook — GitHub, GitLab, or custom) is wired to it.
</Note>

## Webhooks

Separately from pipeline triggers, each project also has a generic outbound webhook registry — you can register a URL, a list of events, and a secret, and Elitea calls that URL when those events occur. This is a different, newer capability than pipeline triggers, keyed on the project rather than a specific pipeline, and it has no equivalent in the legacy platform.

<Steps>
1. Open **Settings › Webhooks** for the project.
2. Select **Register a new webhook**, give it a destination URL, and (optionally) a comma-separated list of event types to fire on — leave the events field blank to fire on every event.
3. Save. The new webhook's secret is shown once, in a dialog with a copy button — save it now, since your receiver verifies every request's `X-Webhook-Signature` header against it.
4. Verify the signature on your receiving end: it's an HMAC-SHA256 of the raw request body, keyed with the secret, the same scheme the pipeline trigger's bearer token protects against.
</Steps>

From the same page you can:

- **Show or hide** a webhook's secret inline (it stays visible to anyone who can read the row; the toggle is a display convenience, not an access boundary).
- **Rotate** the secret — mints a fresh value and shows it once, exactly like creation.
- **Enable or disable** a webhook without deleting it, with the toggle in the Active column.
- **Delete** a webhook, with a confirmation step.

<Note>
The webhook API itself still works with a personal access token, if you'd rather script registration: create an entry with a target URL, the events you want, and a secret Elitea will sign requests with.
</Note>
