# Agent proposals and Copy to project (#1615, ADR-0050 decisions 5a and 1)

An agent version with `meta.capabilities.can_propose_agents: true` gets a
`propose_agent` tool: it proposes that a sub-agent it ran is kept as an agent
of its own. A person reviews the proposal in the chat or in the Agents page's
Proposals inbox, and nothing is saved as an agent until they select Create.
A personal agent also gains Copy to project (a fork plus the memory the
person picks).

- **Who is affected:** operators upgrading Main and the Rust worker.
- **What to do:**
  - **Upgrade every worker before Main.** The proposal travels over the
    existing runtime content gRPC service as a new `ProposeAgent` RPC. Until
    Main is upgraded, a new worker's `propose_agent` call answers
    `proposals_unavailable` to the model and nothing is stored; an old worker
    never offers the tool.
  - Shared migration `0234_agent_proposals.sql` adds the
    `elitea_lifecycle.agent_proposals` table. It runs with the other shared
    migrations; nothing to do by hand.
  - No new permission. Proposing needs the run's person to hold
    `models.applications.applications.create`; the inbox needs
    `models.applications.applications.list`; Create and Copy to project need
    `models.applications.applications.create`. Custom roles keep what they
    have.
- **Behaviour:**
  - The project of a proposal is always the run's project (from the execution
    kernel), never one the worker names.
  - At most 3 open proposals per proposing agent; a dismissed profile is not
    proposed again for 30 days.
  - A created agent starts at the `low` risk tier. Proposed tools are shown
    with their ADR-0041 category but are not bound by Create.
  - Save now refuses a version whose `meta.capabilities` is not an object of
    booleans (422 `capabilities_block_invalid`).
  - Audit: one `ai.elitea.security.v1.agent.proposal.changed` event per
    proposal, creation, dismissal, seeding and copy, with no draft text.
  - Fixes a bug of #1607: every agent-memory write that takes the per-agent
    advisory lock (remember, edit and approve, delete, clear) failed on a real
    database with a pgx encode error on the lock key. The key is now built in
    Go, so these writes work again.
- **Docs:** "Agent proposals and Copy to project" (How-tos, Agents and
  pipelines).
