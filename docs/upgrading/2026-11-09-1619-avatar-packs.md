# Agents: avatar packs, an `agent-media` bucket and a tenant migration (#1619, ADR-0050)

An agent version can now have an avatar pack: a still and one image,
animated WebP, MP4 or WebM loop per agent state. Main stores each file in a
new per-project `agent-media` bucket of the object store that artifacts
already use, and serves it at `/api/v2/agent_media/{project_id}/{sha256}.{ext}`
without a credential, like `/icons`. Main validates every file before it
stores it: the type comes from the bytes, an SVG with a script is refused,
and an animation is at most 4 s, 512 px and 2 MiB, with no audio.

## Migration

Tenant migration `0165_application_version_avatar_pack` adds the nullable
column `application_versions.avatar_pack`. Run the migrations as for every
release. Until a tenant has the column, its versions read with no pack and
its chat participants show `meta.icon_meta` as before.

## Object store

No new setting. `agent-media` is a project bucket inside the object store
that is already configured (object keys `p/<project>/b/agent-media/o/...`);
there is nothing to create. Without an object store, upload and generation
answer 503 `storage_unavailable`; nothing else changes. `agent-media` is now
a reserved bucket name, so a user cannot create an artifact bucket with it.

## Generation

Generate on the agent editor's **Avatar** tab calls the LLM gateway's
`/llm/v1/images/generations` and `/llm/v1/images/edits` under the caller's
identity, so the project budget pays and the gateway request log records it.
It shows only when the project has an image generation model. No new
service, image or worker is needed; nothing runs ffmpeg.

## Permissions

Upload and generation use the existing `models.applications.upload_icon.post`
permission. No new permission, and no role change.
