# Skills: shared publish-check key, stricter icon upload (issues 2100, 2107)

**What changed.** The skill publish check signs its validation token with a key derived from
`APPLICATION_SECRET_KEY`, the same secret every Main replica already shares for the agent publish
check. Before this the key was random per process, so with more than one replica (or a restart
between the check and the publish) a skill that met every requirement was refused with
"Validation token is invalid". A token signed by another key is still refused with
`validation_token_invalid`. Without `APPLICATION_SECRET_KEY` (a development process) the key stays
random per process.

The skill icon upload now judges the file by its bytes: PNG, JPG, GIF, WEBP, BMP and ICO are
accepted, up to the existing size limit, and the whole file must decode as an image of that format.
Anything else (SVG and TIFF included, an empty or corrupt file too) is refused with `400` and a
message. No migration and no new setting.

**Who is affected.** Operators running more than one Main replica; anyone who uploaded a skill icon
in another format through the API. Icons already stored are served as before.

**What to do.** Make sure `APPLICATION_SECRET_KEY` is set and identical on every Main replica
(it already must be). A person who validated a skill just before the upgrade validates it again.
Upgrade Main and the web app together.
