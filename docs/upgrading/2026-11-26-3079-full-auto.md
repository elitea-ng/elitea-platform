# Desktop: Full auto mode for long unattended Local work runs (#3079, ADR-0061 amendment)

**What changed.** The desktop composer's mode menu offers **Full auto** above Bypass for a Local work thread. It
answers every approval Bypass answers and also the trusted folder's taint-gated questions, except a hard-deny list
(recursive deletes outside the folder, credential stores, shell profiles, turning a protection off), which is still
asked, or declined when unattended. It is per thread, confirmed every time, never a default and never inherited by a
hand-off or consult. Client contract 1.69: the native client policy gains `local_work_full_auto` (default `true`),
and a committed turn's `local_work` report gains `full_auto` (`answered`, at most 50 `asks` with `command`,
`reason`, `tainted`, `held`), stored on the answer as `meta.local_work.full_auto`. Web and mobile show
"Ran in Full auto" on such an answer. The desktop host refuses a Full auto start with `full_auto_forbidden` when
the policy, or a Mac's managed `local_work_full_auto` set to `false`, forbids it.

**Who is affected.** Desktop users; administrators of the native client policy.

**What to do.** No action to keep the default (Full auto offered, opt-in per thread). To forbid it, turn off
**Admin › Configuration › Native client policy › Allow Full Auto Mode**, or push `local_work_full_auto = false` in a
macOS configuration profile. No migration.
