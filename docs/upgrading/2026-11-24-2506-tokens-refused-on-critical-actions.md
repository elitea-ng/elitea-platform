# Personal access tokens are refused on critical administration actions (#2592, ADR-0059)

**What changed.** A personal access token whose administration access is
`scoped` or `inherit` (shared 0265) gets `403` with the code
`token_critical_action_refused` on every action of the administration action
table marked `critical` with `token: never`. The refusal is recorded in
`centry.audit_events` with the action `admin.token_refused`. A `none` token is
unchanged: the route gate refuses it as before. A browser session, a desktop
or mobile session, a run token and a project system token are not personal
access tokens, and the rule does not apply to them.

The identity provider and SCIM trust actions say `token: allowed`, the repair
path of ADR-0059 decision 5: they stay open to an `inherit` token whose owner
is a standing global administrator, and are refused to a `scoped` token and
to the `inherit` token of any other administrator. The exception ends at the
sunset of decision 7.

**Routes decided whole.** On a route whose danger depends on what the
request changes, the entry is picked from the request: the `action` field of
`POST /api/v2/admin/auth_users/{mode}` (only `set_admin_role` is refused; a
body whose `action` the rule cannot read unambiguously, or that names no
action of the route, is refused to a token too), or
the identity provider save's own classification (only a trust change or a
turn-off is held to the rule; a rename is not). The gateway governance rows
(`guardrail`), the global provider update (`route`) and the retention writes
(`shorten`) have no classification in their handlers yet, so a `scoped` or
`inherit` token is refused on each whole route, its non-critical changes
included. The refusal narrows to the critical change when those handlers
classify.

**Who is affected.** Automation that used a personal access token for one of
the actions below. Do the action from the console, or, for an identity trust
repair, use an `inherit` token of a global administrator.

**The critical actions.** The table is generated from the action table
(`services/elitea-main/internal/adminaccess/testdata/actions.golden`) by
`node scripts/ci/check-critical-actions-note.mjs --write`; CI fails when it
does not match the registry.
